Irrelevant results usually mean the asset lacks searchable text, the index lags behind, or a strong lexical hit pins another name to first place — not that the model is broken.

Symptoms

  • Colloquial descriptions miss the target asset, and the top results are clearly unrelated.
  • Typing the asset name exactly still ranks the target second.
  • An asset whose tags were just added or changed cannot be found.
  • Searching inside one category returns very little, but searching all assets works.

Possible causes

CauseHow to tellAction
The asset lacks searchable textNo Chinese name, tags, note or AI descriptionAdd metadata, then sync
The index lags behind the libraryindex_lag above 5 seconds, or a stale noticeRun an incremental sync
A strong lexical hit pins first placeThe query happens to match another asset nameUse a more precise name or add a category filter
The scope is limited to one categorySearch runs only inside the current categorySwitch to all assets and search again
The index model differs from the query modelThe status reports a model mismatchUnify the model or rebuild the index
The query is too broad or ambiguousOne phrase could mean several assetsAdd qualifiers such as material, style or purpose

Steps

  1. First type the exact asset name to confirm the target asset itself can be found.
  2. Look at the match field of the results: keyword is a lexical hit, semantic a semantic hit, both both.
  3. Give the target asset a Chinese name, tags, a note or an AI description; all of these fields enter the indexed text.
  4. Run asset_semantic_status to check index_lag; when the index lags, run python tools/asset_index.py --sync.
  5. Switch the search scope back to all assets to rule out filtering by the current category.
  6. Use mode=keyword when you need a purely literal match, and mode=semantic when investigating semantic recall.

Verify the result

The target asset enters the top three, match shows semantic or both, and newly added tags and Chinese names can be found.

If it still fails

  • Record the query, the target asset name and the actual top five results to see whether recall or ranking is the problem.
  • If results are still off right after a rebuild, confirm the model matches the index and no old index directory is mixed in.
  • For ambiguous queries, add qualifiers such as material, color or purpose and compare the results again.
  • Continue with 4.5.9.3 "Irrelevant search results" and 4.5.6.4 "Incremental and full sync".
