菜单只调用无参的 main() / run()；需要参数或结构化返回值时，走命令通道或脚本浏览器的 PARAMS / RESULT 约定。

入口与参数

  • 菜单与命令通道的入口解析顺序一致：main() → run() → 源码含 if __name__ == "__main__" 时以 __main__ 身份执行一次。
  • 菜单调用 main() / run() 时不传参数。
  • 命令通道 quicktool_run 传了 params 时会尝试 fn(params)；入口不接受参数（抛 TypeError）时自动回退为 fn()。
  • 只找到 main / run 时不会再执行模块体，避免顶层副作用执行两遍。

PARAMS / RESULT 约定

脚本式入口可读写两个约定变量：

PARAMS = globals().get("PARAMS") or {}
DRY_RUN = bool(PARAMS.get("dry_run", False))

def main():
    # 在这里执行；写操作建议先 dry_run 并返回前后值
    return {"status": "ok", "updated": 0}

RESULT = main() if not globals().get("SKIP_RUN") else None
  • PARAMS：脚本浏览器「带参数运行…」或命令通道传入的 JSON 对象。
  • RESULT：脚本结果；脚本浏览器会打印摘要，命令通道会把它放进返回值。
  • MEL 没有 PARAMS / RESULT 约定，关键结果请 print。

返回值形状

  • 命令通道可安全返回 None、布尔、数字、字符串、列表、字典。
  • 嵌套字典 / 列表只保留前 30 项，其它对象会转成 repr 并截断到 300 字符；不要返回 Qt 控件等不可序列化对象。
  • GUI 工具通常没有有意义的返回值，命令通道只报 opened: true，表示窗口已打开、任务尚未完成。

结果验证

  1. 先 dry_run=true 调 quicktool_run，确认入口识别正确。
  2. 实际运行后检查返回值中的 status、entry 与 result。
  3. 在脚本浏览器中运行同一脚本，状态栏应显示用时，脚本编辑器中可见 RESULT 摘要。

注意事项

  • 菜单方式不会注入 PARAMS，依赖参数的逻辑要能在缺省值下安全运行。
  • 长耗时或需要取消的任务，建议在脚本内提供自己的进度与取消方式。
