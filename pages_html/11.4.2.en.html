The global model is the provider and model configuration used by default by every feature that needs a large model.

Effect

Configure the provider, API key, API endpoint and model name in one place for reuse by AI thumbnail analysis and similar features.

Values and defaults

  • Provider: Ollama (local, default), LM Studio (local), DeepSeek, Qwen (Alibaba Cloud DashScope), Zhipu (BigModel), Kimi (Moonshot), OpenAI, Anthropic Claude, Custom (OpenAI compatible).
  • API key: required for cloud providers; local services such as Ollama need none and the input is greyed out.
  • API endpoint: empty means the provider's default; a custom provider needs a compatible endpoint.
  • Model: the dropdown fetches the provider's live model list, and a name can also be typed; empty by default.
  • Thinking mode: off by default. When on, the model prints its reasoning before answering, which is only recommended for hard reasoning tasks.
  • Keys are stored per provider, so switching providers never mixes them up.

Using another vendor or a self-hosted endpoint

The plug-in only speaks the OpenAI-compatible protocol (POST {endpoint}/chat/completions, with the model list from GET {endpoint}/models). For any provider not in the dropdown that offers an OpenAI-compatible endpoint, choose Custom (OpenAI compatible) and fill in the endpoint, key and model name:

ServiceWhat to put in the API endpoint
Google Geminihttps://generativelanguage.googleapis.com/v1beta/openai/
Anthropic ClaudeChoose Anthropic Claude in the dropdown (endpoint https://api.anthropic.com/v1/, the official OpenAI SDK compatibility layer)
OpenRouterhttps://openrouter.ai/api/v1
SiliconFlow / Volcano Ark / Moonshot / Baichuan and othersThe "OpenAI compatible" endpoint from each console
Aggregate gateways (OneAPI / NewAPI)http://<your gateway>/v1
Local LM Studio / vLLM / XinferenceLM Studio can be chosen as LM Studio (local) (default http://127.0.0.1:1234/v1); other local services use http://127.0.0.1:<port>/v1

Notes:

  • Do not repeat /chat/completions at the end of the endpoint; stop at the /v1 level;
  • When no model list is available, type the model name directly;
  • For a local service that wants no key, any placeholder value works (the custom provider's key input is enabled);
  • Azure OpenAI (api-key auth header, deployments/<deployment name> path and api-version parameter) and the native Anthropic / Gemini protocols (/v1/messages, generateContent) do not use the OpenAI-compatible format, so the current version does not support them directly — prefer the vendor's compatible endpoint or a gateway such as OneAPI that converts to OpenAI compatibility.

Thinking mode

It is off by default. Thinking (the reasoning process) and the answer share output tokens, so for tagging, classification and one-line descriptions it only makes things slower, and with a tight budget the answer itself can come back empty — which is why everything that can be off defaults to off.

Only scenarios needing multi-step reasoning (complex descriptions, difficult judgments) are worth enabling 「开启思考模式」 (Enable thinking mode).

How each provider behaves:

ProviderWhat happens when it is off
OllamaThe OpenAI-compatible endpoint gets reasoning_effort: none (verified); the native endpoint gets think: false
DeepSeek / Zhipu (regular models)Sends thinking: disabled
Zhipu glm-5.2 / glm-5.3Always thinks and cannot be turned off → drops to the lowest level when off
OpenAI o series / GPT-5Cannot really be turned off → uses reasoning_effort: low when off
Kimi / Claude compatibility layer / custom / LM StudioNo universal switch, keeps the server default

Tip: an empty answer with thinking on usually means max_tokens was consumed by the reasoning, which is unrelated to the switch itself.

Scope

  • Features that need a large model, such as AI thumbnail analysis, read this configuration by default.
  • AI search only calls it when 「使用全局大模型」 (Use the global model) is checked in the search configuration; otherwise it does local vector retrieval only.
  • Semantic search and search by image use the local Ollama embedding model and are unaffected by this chat model.
  • The configuration is stored in app_settings.json under ai_provider, ai_api_keys, ai_base_url and ai_model.

When to change it

  • You have a paid cloud model service and want faster analysis than local.
  • You use a proxy or self-hosted OpenAI-compatible endpoint: choose 「自定义（OpenAI 兼容）」 (Custom, OpenAI compatible) and fill in the endpoint and model.
  • Local only: keep Ollama and finish "AI dependency check and install" first.

Tips

Tip: cloud providers need a network, and the thumbnails and prompts used for analysis are sent to that provider; local Ollama never leaves this machine.

Tip: API keys are stored as plain text in app_settings.json, so never send that file out.
