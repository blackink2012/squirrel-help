一句话定位：插件所有可调的东西都在这里，分十个页签；大部分页签默认是「锁住」的，要先勾「解锁全部配置」才能改。

第一次打开设置的人十有八九会卡在同一件事上：明明看到选项，却点不动、打不了字。那不是坏了，是全局锁定（见下面「最容易卡住：全局锁定」）。

怎么打开

  1. 主窗口顶部工具栏，点「设置」按钮（齿轮，见 8.2.4）；
  2. 弹出「设置」窗口，默认停在「常规」页；
  3. 点左侧竖排的页签切换页面（页签在窗口左边，长英文标签也放得下），改完点底部按钮保存。

最容易卡住：全局锁定

默认状态

窗口底下有一个复选框「解锁全部配置」，默认不勾。此时除了「常规」「AI 设置」「授权激活」「关于」四页，其余六个页签里的复选框、输入框、按钮全部是灰的：

页签未解锁时
导出默认值勾选框灰、锁定开关灰
右键菜单菜单项开关灰、双击命令单选灰
支持格式文本框只读
贴图后缀别名文本框只读（页内「恢复默认设置」按钮也灰）
子库与分类子库列表、ID / 显示名、分类列表全灰（「显示在主 UI」复选框仍可点）
其它配置文本框只读

解锁步骤

  1. 勾选「解锁全部配置」；
  2. 弹出「配置修改警告」，列清哪几个页签会被解锁，并提醒「错误的配置可能导致资产库功能异常」；
  3. 点「是」→ 六个页签全部可编辑；点「否」→ 复选框自动退回未勾，什么也没发生；
  4. 改完记得保存；取消勾选「解锁全部配置」会重新锁上（不会自动保存）。
警告

锁不是安全边界，只是防误触。解锁后改的是资产库的底层行为（导出格式、右键菜单、文件识别、贴图通道识别），改错可能导致导入导出异常。

解锁状态下的二次确认

在解锁状态下点「应用」或「确定」，还会再弹一次「配置变更确认」（当前为解锁状态，非通用配置可能已被修改…是否仍要应用当前设置？）。点「否」= 这次不保存。

恢复默认到底恢复了什么

点「恢复默认设置」并确认后，下面这些会立刻在界面上回到默认值（还需要点「应用 / 确定」才真正落盘）：

恢复的项恢复到
字体大小 / 界面缩放 / 缩放锚13 / 自动 / 跟随系统缩放
默认视图 / 同名冲突图标网格 / 自动重命名
导出默认值重新从 export_preset.json 读取（丢弃未保存的改动）
贴图后缀重新从 pbr_mapping.json 读取（丢弃未保存的改动）
右键菜单重新从 context_menu_preset.json 读取（丢弃未保存的改动）
其它配置回到内置出厂列表（几何体 / 图像扩展名、材质节点类型）

不会恢复的项（容易误会）：

  • 「支持格式」页的扩展名列表（要手动改回或从备份恢复）；
  • 「子库与分类」页的子库 ID / 显示名 / 默认分类列表；
  • 「常规」页里的资产库列表、贴图 / 依赖导入策略、导入命名空间、语言、配色、缩略图大小；
  • 「AI 设置」页的所有内容（依赖、大模型、外部连接）。

也就是说：「恢复默认设置」≠「恢复出厂」，它重读的是磁盘上的预设文件，文件里是什么就恢复成什么。

提示

想要真正的「恢复出厂」，用「常规」页最底下的 设置预设 → 还原预设：它把 app_settings.json 里的全部界面偏好写回默认值并立即生效（API Key 与资产库列表保留），范围与流程见 8.9.2 的「设置预设」。

配置文件在哪

设置分布在两类文件里（<插件目录> 指插件安装目录下的 squirrel_asset_manager）：

文件存什么
<插件目录>\Assets\preset\config.json资产库列表与默认库、同名冲突策略、贴图 / 依赖导入策略、支持格式、子库与分类、其它配置、常用标签等
<插件目录>\Assets\preset\export_preset.json「导出默认值」页（按资产类型分别保存）
<插件目录>\Assets\preset\context_menu_preset.json「右键菜单」页的菜单项开关（按子库分别保存）
<插件目录>\Assets\preset\double_click_preset.json「右键菜单」页的双击命令（按子库分别保存）
<插件目录>\Assets\preset\pbr_mapping.json「贴图后缀」页的通道别名
%USERPROFILE%\.squirrel_asset_manager\app_settings.json字号、界面缩放、主题、语言、默认视图、缩略图输出尺寸、桥接端口开关、全局大模型、隐藏的顶级分类等界面偏好
%USERPROFILE%\.squirrel_asset_manager\settings_preset.json「常规 → 设置预设」保存的整套界面偏好快照（可用「导入 / 导出预设」搬走或恢复；不存在 = 还没保存过预设）
提示

手改这些 JSON 前先备份，并且最好先关掉插件窗口。JSON 写坏时插件会尽量回退到默认值，但「恢复默认设置」只重读文件、不修复文件本身。
