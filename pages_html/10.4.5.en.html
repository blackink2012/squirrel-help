Rendering frames uses the current renderer for a final per-frame render; it is much slower than a viewport screenshot and suits finished images once framing and materials are confirmed.

Prerequisites

  • The scene's render settings are configured and the current renderer is available.
  • The frame range, output directory and resolution are decided; rendering cannot be undone.

Steps

  1. Call render_frames; frames accepts "1-3", "1,5,9", "1-10:5" or a plain array.
  2. Set the output directory image_dir; without it the scene's own output prefix is used.
  3. To override resolution pass width / height (0 means use the scene settings).
  4. Choose the camera and the file name prefix; in an Arnold scene samples temporarily changes AASamples.
  5. Limit this call with max_frames, 100 by default.

Verify the result

It returns each frame's output path and progress; open the images and confirm resolution, frame numbers and content. Images already rendered are kept after cancelling.

Tips and warnings

  • Each frame takes tens of seconds to minutes, so this is a long job: run it as an async job and watch the progress.
  • The command temporarily bakes the frame number into the output prefix and turns animation off, restoring both afterwards; otherwise one call would render the whole range or overwrite every frame with the same file.
  • Rendering cannot be undone; samples only applies when the scene already has a defaultArnoldRenderOptions node.
  • Repeated in-process Redshift renders in the same Maya session risk a crash; see "Renderer crashes".
