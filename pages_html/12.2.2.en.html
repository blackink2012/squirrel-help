A risk level only describes a command's blast radius; there is no approval gate. All three levels execute directly, and the caller should decide from the level whether to run dry_run first.

Of the current 146 commands, 42 are readonly, 67 are low and 37 are high (counted from generated/commands.json).

The three levels

LevelMeaningTypical commandsdry_runundo_last
readonlyRead-only; changes neither the library nor the scenesearch_assets, get_asset_info, scene_info, list_categoryNot supportedNot needed
lowReversible write with a clear scopemove, rotate, rename, set_visibility, set_attr, assign_materialSupportedSupported
highDestructive, bulk, or runs arbitrary codedelete, batch_delete, batch_move_to, maya_run_python, maya_run_melSupportedMostly supported, see below

Usage rules

  • Read-only commands have no preview branch; they return the current facts.
  • Low-risk write commands return status="preview" with dry_run=true, listing the objects or fields that would change.
  • High-risk commands should be checked with dry_run first; the broker never returns approval_required, so seeing that status means the host is running old code.
  • The contract requires high-risk commands to offer rollback or undo: library writes use snapshots, and delete_objects uses Maya's own undo stack. maya_run_python / maya_run_mel are explicit exceptions — they try to wrap the whole call in one Maya undo chunk, but undo_last does not cover them, so back up the scene yourself before running.
  • The universal execution channel is off by default: enable allow_maya_exec in settings to use it (the first enable goes through a separate consent dialog). The environment variable SQUIRREL_ENABLE_MAYA_EXEC=1 forces it on.

Warning: risk_level does not block a command. It is only a judgement aid for the caller and the user; destructive operations still require confirming the target and making a backup.
