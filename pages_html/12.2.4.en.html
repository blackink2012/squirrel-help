Execution mode is declared by the command: the 9 commands with execution="async" should go through the job entry, since a synchronous wait hits the 30-second cap.

Submission returns a job_id immediately; query it with GET /jobs/<job_id>. The state machine is queued → running → done / error / timeout / cancelled / interrupted. By default there are 4 worker threads, a queue limit of 32 and a per-command default timeout of 60 seconds; finished jobs are kept for 1 hour, up to 200 entries. When the queue is full you get QUEUE_FULL; check /jobs before submitting again.

Progress

Commands that support progress receive a callable progress(percent, message, **extra). percent is clamped to 0–100, message is cut to 200 characters, and extra keeps at most 8 scalar fields. Progress frames are emitted at most every 0.4 seconds, but the final frame on completion is always delivered; progress_age_secs tells you how old a progress report is.

Cancellation

Seven commands currently declare cancel_supported=true. Cancellation is cooperative:

StageEffect
queuedTruly cancelled; the command was never dispatched to the host
running and the command checks for cancellationStops at the next checkpoint, the job is marked cancelled and returns partial results
running but the command never checksIt cannot stop; it runs to completion and is marked cancel_ignored

Long loops you write yourself should call cancelled() or cancel.raise_if_cancelled().

Warning: A synchronous timeout does not mean failure. The command may still be running on the Maya main thread and its result goes to the late-results mailbox (GET /late_results); check the mailbox before rerunning. Job history lives in <dsh_home>/ai_jobs.jsonl; jobs left over after a broker restart are marked interrupted and are not replayed automatically.
