Exporting a .zlight reports 「不支持的灯光类型」 (unsupported light type), or after import fewer lights exist or types were replaced by approximations.

Symptoms

The Script Editor prints 不支持的灯光类型: <node type>; the asset has fewer lights than the scene; after import a dome light became a directional light, or a spot became a point light.

Common causes

  1. The light type is not registered as a generic type, for example ambientLight, volumeLight, aiLightBlocker, VRaySunTarget, RedshiftPortalLight or RedshiftNightSky.
  2. The target renderer has no equivalent: Arnold has no native spot or distant light, and native Maya has no dome light.
  3. The current renderer is not Arnold, V-Ray or Redshift, so the automatic conversion on import never triggers.
  4. The light is nested under other nodes and was not collected as a light shape at export.

Steps

  1. Select the light, confirm its node type and check the light type table in 7.4.2 to judge whether it is supported.
  2. Switch to a supported light: area, point, spot, directional, dome, disk, cylinder or ies.
  3. When the approximate effect must be kept, choose the replacement for the target renderer: aiPhotometricLight for an Arnold spot and aiSkyDomeLight for an Arnold distant light.
  4. Confirm the renderer plug-in is loaded, then export or import again.

Verify the result

Re-exporting logs 「找到 N 个灯光 shape」 (found N light shapes) with N matching the number of supported lights in the scene; after import the Outliner's light count matches the asset and no unsupported-light-type message appears.

If it still fails

  • Helper lights (portal, blocker, night sky) never enter a .zlight and must be saved as a separate .ma asset.
  • An approximate type does not preserve every physical property of the original; add parameters manually in the target renderer when needed.
  • Cross-renderer conversion needs the matching .mmap; without one the original light is kept and a message is printed.
