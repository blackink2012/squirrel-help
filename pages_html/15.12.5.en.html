One-line summary: when exporting, if the target category already holds a folder with the same name, the plug-in stops and asks: auto rename, type another name, or overwrite.

When it appears

  • Clicking Create asset (or Update asset → Replace asset) when the target category already holds a .zasset with that name.
  • In batch export it checks and asks one by one; each same-name item gets one question.
  • When Name conflicts in settings is set to auto rename / manual input, this window no longer appears and the configured policy applies directly.

Window content

The first paragraph is a warning: "A folder with the same name as asset '<name>' already exists; continuing the export will overwrite the existing files."

Results of the three handling options

To overwrite an old asset: this window offers no direct "overwrite" radio — the overwrite path is Update asset → Replace asset, which has its own confirmation ("overwrite it with this export? the original content will be replaced").

A complete example

  1. Click Create asset.
  2. The asset name conflict window appears.
  3. Keep the default auto rename (append _001, _002 …).
  4. Click OK.
  5. The export continues and the grid gains an xxx_001 asset while the original xxx is untouched.

Changing a remembered choice back

  • Open Settings → Asset library page → Name conflicts:
    • Ask every time (ask how to handle same-name assets during export)
    • Auto rename (append _001, _002 …)
    • Manual input (open a dialog to type a new name)
  • Choosing Ask every time restores the window. Details are in 4.8.3.2.

Troubleshooting

SymptomCauseWhat to do
No window appeared and an _001 asset showed upThe settings policy is auto rename and was rememberedChange it back to ask every time in settings
After typing a new name it reports that it exists tooThe new name collides as wellChoose another, or switch to auto rename
Batch export asked many timesOne question per same-name item (by design)Tick remember my choice to settle it at once
