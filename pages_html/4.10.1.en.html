A version is one content iteration of the same asset and a LOD is one geometry detail level inside a version; both are stored in the same .zasset.

Key nouns

  • Main version: the content in the asset root, including meta.json, node.*, textures/ and so on; every asset has a main version.
  • Embedded version: the V1/, V2/ directories inside the main asset, each a complete self-contained asset. The main asset's meta.json records {id, folder, label, tag} under version_assets.
  • LOD: lod0 is the geometry in the root, and lod1 onward live in lod{n}/ sub-directories; the manifest is lods.json, created the first time a LOD is appended.
  • Default version / default LOD: recorded in meta.json and lods.json respectively, and read by import and version management.

Directory layout

Crate.zasset/
├── meta.json          # includes the version_assets registry
├── node.ma            # main version geometry (lod0)
├── lods.json          # LOD manifest (lod1, lod2…)
├── V1/                # embedded version (complete and self-contained)
│   ├── meta.json
│   └── node.ma
└── V2/
    ├── meta.json
    └── node.ma

Why it is organized this way

Different forms of one asset do not need to become separate grid assets: content iterations go into versions, distance-based detail goes into LODs, and when materials must differ a version can carry its own materials.

注意

Variants and versions are two parallel models: variants are recorded in the variants section of variants.json, their geometry sits flat under variants/, and textures and materials are inherited from the asset root; embedded versions remain complete self-contained V{n}/ directories. The versions section of older assets is kept for read-only compatibility and is listed together with embedded versions. See the "Variants" section for variant usage.
