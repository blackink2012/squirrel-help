The assistant in the chat surface does more than talk: it calls the tools the plug-in registers to search assets, read the scene and run scripts, and those tools are routed to the current Maya through the local backend.

What the assistant can use

  • Command surface tools: squirrel_list_instances, squirrel_list_commands, squirrel_execute_command, squirrel_execute_batch.
  • Long jobs: squirrel_execute_async returns a job ID that squirrel_jobs can query or cancel; results that miss the timeout are fetched with squirrel_late_results.
  • Fallback channel: squirrel_maya_bridge, which goes straight to Maya's commandPort when the backend or instance is unavailable.
  • Documentation and dependencies: maya_docs looks up commands, nodes and the API; squirrel_ai_deps checks or installs AI dependencies.
  • Knowledge: the bundled skill set provides operating discipline and scene recipes, landing in <dshHome>/skills.

Instance binding

By default it binds to the Maya instance this conversation belongs to, so commands may omit the instance ID. With several Maya sessions open, operating another one requires explicitly allowing cross-instance work; the assistant will not switch for you.

Models and credentials

Which model the conversation uses is managed by dsh itself; on the first chat follow its prompt to sign in or enter an API key. The plug-in does not manage those credentials.

Boundaries

  • Tool calls respect command risk levels; high-risk commands should be previewed before running.
  • When squirrel_* tools are missing from the panel, first confirm the skills landed, the backend is running and the current Maya is registered; dsh_status lists all of these states at once.
