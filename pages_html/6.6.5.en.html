Where textures and linked files land on import is decided by two settings in Settings → 常规 (General): the texture import policy and the dependency file import policy.

OptionTexture locationLinked files and references
Copy textures into the project / copy into the projectProject sourceimages/squirrel_asset/<asset name>_<last 4 of ID>/Project cache/squirrel_asset/<asset name>_<last 4 of ID>/; references go to references/squirrel_asset/<asset name>_<last 4 of ID>/
Current asset directoryReads the files inside .zasset/textures/ directly, no copyReads the files inside .zasset/deps/ directly, no copy
Source file directoryKeeps the original absolute paths recorded at export, unmodifiedKeeps the original absolute paths recorded at export, unmodified

Where they apply

  • The texture policy applies to ma/mb import, zmetal material import, zlight light import, texture import, HDR texture assignment and environment light creation.
  • The dependency policy applies to ma/mb import and 「添加引用」 (Add reference), preferring a full source-path match against meta.dependency_map and falling back to file-name matching.
  • Both policies are persisted in Assets/preset/config.json; the current repository default is asset_directory, and the Settings window shows the effective value.

Recommendations

  • Library and project on the same machine, with asset directories often reorganized: choose 「当前资产目录」 (current asset directory) so no copies are made.
  • The project must be copied elsewhere or handed to someone else: choose 「拷贝到项目」 (copy into the project), which gives the most stable paths.
  • Source files live at fixed locations and disk space is tight: choose 「源文件目录」 (source file directory); once a source file moves, textures and dependencies break.
