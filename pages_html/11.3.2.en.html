Duplicate name handling decides what happens when exporting an asset whose target location already holds a same-named asset.

Effect

When exporting or creating an asset meets a same-named target, the preset policy is applied so nothing is overwritten by accident.

Values and defaults

PolicyBehavior
Ask every timeOpens a dialog to choose auto rename, type a new name, or cancel
Auto renameAppends _001, _002… automatically
Manual inputOpens an input box for a new name
  • The current preset file defaults to 「自动重命名」 (Auto rename) (name_conflict_policy.mode = auto_rename); when that key is missing the interface also falls back to auto rename (NameConflictDialog.DEFAULT_MODE), so there is a single default across the whole chain.
  • A choice made under "ask every time" can be remembered with 「记住选择，不再提示」 (remember this choice, do not ask again), and later exports follow the remembered policy.

Scope

  • It only affects the target-already-exists case when creating a new asset; existing assets are never auto-renamed or deleted.
  • Appending a LOD or creating a new version are explicit actions in the export dialog and do not use this policy.
  • It is stored as name_conflict_policy in Assets/preset/config.json.

When to change it

  • Use 「自动重命名」 (Auto rename) for batch exports that must not be interrupted.
  • Use 「每次询问」 (Ask every time) when every name should be confirmed.
  • Use 「手动输入」 (Manual input) with a fixed naming convention that needs human naming.

Tips

Tip: auto renaming only changes the new asset's name and never touches existing assets.

Tip: the policy is written to the preset file after clicking 「应用」 (Apply) and applies from the next export.
