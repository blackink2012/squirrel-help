The color space decides whether texture values are converted to linear: color textures use sRGB, while data textures such as normal, roughness and metalness use Raw.

Texture types and color spaces

Texture typeColor space
baseColor / albedo / diffuse / colorsRGB
emissive / subsurface colorsRGB
normalRaw
roughness / metallic / ao / arm / ormRaw
height / opacity / clearcoat / specular / anisotropy / iorRaw

When creating a material from PBR textures the plug-in reads these rules from Assets/preset/pbr_mapping.json and sets each file node's colorSpace automatically.

Steps

  1. Create the material with a texture asset or the PBR texture workflow; the tool sets the color space of every file node per the rules.
  2. Select the file node in the attribute editor and check that colorSpace matches the table above.
  3. Do not change an HDR connected to a dome light to sRGB by hand; the plug-in treats it as Raw when connecting and also enables ignoreColorSpaceFileRules on import.
  4. If textures look off after importing an asset, check file.colorSpace first and then whether Maya's file rules re-derived it.

Verify the result

Color textures show sRGB and normal and data textures show Raw; normal maps no longer look grey or off-color, roughness values match the source file and the HDR environment has a normal brightness.

Tips

  • When importing .zmetal / .ma the plug-in protects existing colorSpace values while rewriting texture paths, so the png/jpg defaults do not override them.
  • The image format conversion tool only converts pixels and bit depth and never writes color space metadata; HDR/EXR to 8-bit also applies tone mapping.
  • Setting a color texture to Raw makes it darker and oversaturated; setting a data texture to sRGB distorts normals and roughness.
