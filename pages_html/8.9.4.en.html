For a timeout first decide whether the model is slow, the backend is not running, the network is blocked or the Maya main thread is busy; each layer is handled quite differently.

Common symptoms and fixes

The first semantic search or AI analysis is slow: a model needs time to load the first time; wait or retry once, and it should become clearly faster.

Ollama request timed out: confirm http://127.0.0.1:11434/api/tags opens; if the system or environment sets a proxy (HTTP_PROXY / HTTPS_PROXY) without 127.0.0.1 in NO_PROXY, even loopback requests are intercepted. Raise SQUIRREL_EMBED_TIMEOUT when needed.

Cloud endpoint timed out: check the API endpoint, key, network and proxy; try another available model.

AI assistant reports the web client failed to start with an empty log and exit code 0: almost always the Node version is too old and must be ^22.19 || >=24. Use the one-click install for portable Node, or point SQUIRREL_NODE at a qualifying interpreter.

The backend is unreachable: confirm it is running and read the actual port from ~\.squirrel_asset_manager\broker_endpoint.json; it switches ports automatically when one is taken.

A Maya command never returned: the main thread may be busy. Check late results and job state first, and never rerun a destructive command just because of one timeout.

Verify the result

The timing-out item returns normally, squirrel_list_instances shows the current Maya, and another dependency check reports no new gaps.

If it still fails

Use the crash / disconnect diagnostic tooling to check whether the port is really answering or merely listening; listening does not mean healthy.
