One-line summary: these two items are the front door for "bring asset content into Maya". How they look on the menu depends on how many importable formats the asset holds.

Sub-libraries without a generic Import are not unable to import; they each have a more specific entry — see their own pages.

The three forms of Import on the menu

FormWhen it appearsExample
Single row "Import <format>"The asset has only one usable formatModels: Import ma; HDR: Import hdr
"Import ▶" submenuThe asset has several usable formatsMaterials: zmetal / ma; lights: zlight / ma; animation: ma / abc
Sub-library specific entryThat sub-library's import is more than "import a file"Textures Import textures ▶, images Import as file node, audio Import to timeline…, animation data Import animation ▶

Every submenu item is a "format name" (even with a single format the row reads like "Import ma"), and choosing one imports in that format.

"Import ▶" may also contain "import version / LOD"

When the asset is a master asset with versions, variants or several LODs, the Import ▶ submenu gains a block of internal items (the heading varies with content):

ItemDescription
Import variant / version ▶ (or "Import variant ▶", "Import version / LOD ▶")Expands the asset's versions / variants / LODs so you can import just one of them
Version nodes (such as V1, V2)The version itself; go in and pick its LOD or geometry format
VariantVariant entries, whose label carries a face count (such as "— 12,345 faces")
Main versionThe content of the asset's main version
View versions / view variants / view LOD managementNot imports but a switch of the asset area into an "internal view" that browses internal entries like folders

The context menu of internal entries themselves (a reduced version) is in 8.5.18.

The two forms of Add reference

FormWhen it appears
Single row "Add reference"The asset has only one referenceable format
"Add reference ▶" submenuThe asset has several referenceable formats (typically animation's ma / abc)

The referenceable formats are always this set: .ma / .mb / .fbx / .abc / .usd / .obj. When the asset holds none of them, the row does not appear.

Import or reference?

What you wantChooseWhy
Edit geometry or material in the sceneImportWhat comes in is real editable nodes
Just place it / follow asset updatesAdd referenceThe scene stores only a path, so reloading picks up asset updates
Keep the scene file smallAdd referenceContent stays in the asset package and is not written into the scene

The price of referencing: moving, renaming or deleting the asset package breaks the reference (the scene then reports a missing file). Importing has no such problem, but content enters the scene and later asset changes do not follow.

What you see after clicking

  • Import: content is created in the current scene; materials, lights and node trees select the newly created nodes automatically so you can keep working. When the current renderer differs from the asset's source, a "convert?" prompt appears once.
  • Add reference: a reference node appears in the scene (marked as a reference in the Outliner) and the file itself is untouched.
  • Clicking import / reference with a multi-selection: it runs once for every selected asset (same format), not only the one you right-clicked.

Notes

  • Import does not copy asset files: materials are still read from the package, so moving the package loses the textures in the scene.
  • Name conflicts ask first: when a node with the same name exists, the setting decides (ask / auto rename / overwrite), see 4.3.6.1.
  • Where the docs say "Import", the UI may read "Import ma": the same command with a different look; it is not two features.
