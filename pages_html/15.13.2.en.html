One-line summary: a separate model configuration for AI search — choose a provider, enter a key and address, pick a model.

It is the small window behind the ⚙ button at the top right of the AI search window and only governs AI search. Note that it is a different configuration from the global model in Settings → AI settings: changing this does not affect AI thumbnail analysis, and vice versa. The reason is practical — search needs to be fast and cheap while analysis needs to understand images, so they naturally pick different model tiers.

How to open it

  1. Open the AI search window (see 8.13.1);
  2. Click the ⚙ (AI service configuration) button at its top right.

The four fields

ControlEffectHow to fill it
ProviderWhich vendor's model API to use. Options: Ollama (local), DeepSeek, Qwen (Alibaba Cloud DashScope), Zhipu (BigModel), OpenAI, custom (OpenAI compatible)With Ollama installed locally choose Ollama (local) — no key and no network; for cloud choose the matching vendor
API keyThe key for a cloud provider; local services do not need oneRequired for cloud providers; the input is a password field showing dots. With Ollama the row grays out and clears
API addressThe endpoint. When switching providers, if the current value is still some default address it is automatically replaced by that provider's defaultUsually leave it; change it only for a proxy / relay (custom must be filled in)
AI modelThe model actually used for intent analysis. The dropdown is fetched live from the provider, and you can also type a model name directlyPick one from the list, or type the model when you know it

Behaviors to know

  • The model list is fetched live, not hard-coded. Opening the window, switching provider, or changing the API key / address and pressing Enter all refetch it; while loading it shows "fetching model list…".
  • When the list cannot be fetched the dropdown holds only "(cannot fetch model list, check the address / API key)" — the address or key is wrong, fix those first.
  • Choosing a model saves immediately (still there after restarting the plug-in) and does not wait for OK.
  • Clicking OK before the list finishes loading is blocked with "the model list has not finished loading, please wait" — this prevents storing an empty model name.
  • Cancel only discards this session's page changes, while model selections already saved live stay on disk. To truly return to the old state, select the previous provider / model again.
  • This configuration only affects AI search's intent analysis. It does not take part in retrieval when use global model is unticked in the AI search window.

A complete configuration flow

  1. AI search window → ⚙;
  2. Choose the provider (on first use, validate the path with Ollama (local));
  3. For a cloud provider enter the API key; the default address is correct, leave it;
  4. Wait for the AI model dropdown to change from "fetching model list…" to a real list;
  5. Pick a model (or type its name);
  6. Click OK;
  7. Back in the AI search window tick use global model, send a sentence and check which mode the result note reports.

What you see afterwards / how to undo

  • Once configured, AI search performs intent analysis with these settings; the note above the results reflects the current mode.
  • To undo, switch the provider back (to Ollama (local), for example) or reselect the previous model. Everything here only affects AI search and never touches the library or the scene, so the worst case is inaccurate search.
