A version represents a different design draft of the asset and a LOD represents a different detail level of the same version; both are chosen at import time.

Version versus LOD

ConceptMeaningStorageEffect on import
VersionDifferent design drafts of the same asset (such as V1, V2)A version directory under the parent asset, or variants/ on older modelsDecides which design is imported
LODDifferent detail levels of one version (such as lod0, lod1)Indexed in lods.json; lod0 points at the version root geometry and the rest live in sub-directoriesDecides how many faces are imported

Selection rules

  1. The context menu's 「导入版本 / LOD」 (Import version / LOD) only appears with several versions or several LODs on the main version.
  2. Choose the version first and then the LOD; the menu shows the LOD label and face count.
  3. When one LOD has several geometry formats, choose the format last.
  4. Without a choice the default_lod from lods.json is used; with no index the default geometry is taken from node.* in the root.

Why they are separate

Versions preserve design iterations and LODs control scene cost. Keeping them apart lets you switch detail levels inside one version without affecting the others.

Tips

  • A version root's .zmetal and .mcm appear in the submenu alongside the geometry files, and choosing them runs a material import.
  • To use only the current version's own materials, import its .zmetal from that version directory after importing the geometry.
  • The version and LOD indexes are written during export; editing the directories by hand does not update the index.
