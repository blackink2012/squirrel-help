贴图或依赖缺失，通常是打包时没有收集到文件，或导入后路径仍指向作者机器、临时目录。

症状

  • 导入后材质变黑、变粉，或视口显示棋盘格。
  • file 节点的贴图路径指向不存在的盘符或作者机器目录。
  • 代理、缓存、ABC 或 USD 引用缺失，模型只剩空组。
  • 一个资产里只有部分贴图丢失，其他贴图正常。

可能原因

原因判断方法处理
导出时没有收集关联文件资产目录里缺 textures/ 或 deps/导出时勾选收集关联文件
贴图原本在工程外路径指向 X:/Megascans/... 等外部目录把源文件放到可访问位置后重新导出
手工复制 .zasset 不完整目录里文件数量明显偏少删除后用库内复制/导入流程重新获取
导入后相对路径断开贴图文件名在，但路径基准不对重新导入资产，让路径按资产目录解析
代理类型不匹配缓存/代理节点类型与渲染器不一致确认 V-Ray、Redshift、USD 对应节点
权限或网络盘问题文件存在但读取失败恢复权限，或先把资产复制到本地盘

解决步骤

  1. 打开 .zasset，确认 textures/、deps/ 中是否真的有对应文件。
  2. 在导出端重新勾选「收集关联文件」，并确认源贴图、缓存、代理文件都能访问。
  3. 用依赖扫描查看缺失数量与具体路径，先补齐源文件，再重新导出。
  4. 删除旧的空壳或不完整资产，从库内重新导入，不要手工复制半个目录。
  5. 代理资产要确认物体连接了对应节点后再收集：V-Ray、Redshift、USD 各有自己的代理节点类型。
  6. 导入后如果路径仍指向作者机器，确认贴图文件已在资产目录内，再触发一次导入路径重写。

结果验证

材质的所有 file 节点路径都存在，视口渲染正常，依赖扫描的缺失数量为 0。

仍不行怎么办

  • 用 Maya 的 File Path Editor 查看哪些贴图仍然断链，记录文件名与期望目录。
  • 如果只有代理或缓存缺失，确认导出时对应节点确实存在，而不是只有空组。
  • 按 4.1.12.3「依赖扫描」和 4.2.7.2「依赖缺失」进一步定位。
  • 反馈时附缺失文件清单、资产目录结构和导出日志中的「缺失 N」一行。
