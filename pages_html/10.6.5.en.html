Headless jobs report state through a progress file in the working directory; cancelling also ends the child process tree so no render leftovers survive.

Progress of a headless job

The parent process polls progress.json, whose fields include:

  • running, index / total, label: whether it runs, which item is current and the current asset name.
  • phase: the current stage, showing "cancelling" while cancelling.
  • ok / failed / error: finished and failed counts plus the error.
  • seconds: elapsed time.

Polling is non-blocking and the interface refreshes on a timer, so the window never freezes.

Cancelling

  1. Click cancel in the progress window.
  2. The parent process sets _cancelled and runs taskkill /F /T on the child, ending the whole process tree.
  3. When results are collected, cancelled=true and the log states the reason.

Verify the result

The job process should exit after cancelling; use python maya_bridge.py --doctor to check for leftover mayabatch / Render / kick / oiiotool processes.

Tips and warnings

  • Arnold's kick does not exit by itself after rendering, so cancelling must kill the whole tree; killing only the parent leaves hundreds of MB of zombie processes.
  • Long loops run through maya_run_python must call progress(...) themselves and check if cancelled(): break; code without checkpoints cannot be stopped.
  • On a job timeout or disconnect check late results first, and never rerun a destructive task just because of one timeout.
  • If the worker exits abnormally without a result.json, the result says "the worker produced no result file"; read the end of the log to locate the cause.
