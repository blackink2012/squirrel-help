One-line summary: pick a batch of .ma / .mb files, write a piece of MEL or Python, and run it in every file, optionally saving after each one.

The window is titled "Maya batch script runner". It suits work where "the same thing must be done to dozens of scene files": batch rename, clear selections, add lights, set render options…

A complete flow

  1. Copy the files to process first (important, see the risks) and operate only on the copies;
  2. Quick tools → Batch process Maya files;
  3. Add files and include those copies;
  4. Choose MEL or Python and write the script; use MEL example / Python example as a starting point;
  5. Click Test run (current scene) first: it runs the script in the scene you are currently looking at, so test in an empty or temporary scene;
  6. Once it works, untick Save files after execution and click Run batch for a dry run, watching the log for mass failures;
  7. When that looks right, tick Save files after execution and click Run batch again;
  8. Read the success / failure statistics at the end of the log and handle failures by file name and reason;
  9. Click Save log if you need a record.

Where the output lands

  • The script's effect lands inside each Maya file (written back only when Save files after execution is ticked);
  • The window only produces logs: each result, failure reason and the final statistics;
  • After a batch it tries to reopen your original scene (the path was remembered beforehand); if reopening fails the log does not emphasize it and your scene stays on the last file of the batch — do not save casually then.

Risks and how to undo (the most important part of this page)

  • Run batch defaults to headless execution (a separate mayapy process) and does not occupy the current Maya; only when you untick Headless execution does it open files one by one in the current Maya process, and then:
    • the current scene is replaced during the run (it tries to reopen the original afterwards);
    • save any unsaved changes in the current scene before running, or they may be lost;
    • do not use this Maya while the batch runs.
  • Save files after execution overwrites the source files on disk, with no versions and no recycle bin. That is exactly why you must copy first: copy the files into another directory, batch only the copies, and the originals never change. This is the only reliable fallback.
  • The three advanced checkboxes (back up before execution / force save / ignore errors) are not wired into the execution flow in the current version, so do not entrust safety to them. The actual behavior is fixed: a file fails → log it → continue with the next.
  • Script risks remain: a broken script fails dozens of times in a row, which is why step 5 (Test run) is mandatory.
  • To undo: if the originals were untouched, just start over; if a copy is damaged, copy it back from the backup.
