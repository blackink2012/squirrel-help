排查顺序是「先看状态，再动手」：桥接体检确认 Maya 是否活着，底座接口确认实例与作业，索引与 AI 体检确认检索链路。

Maya 桥接

在项目根或插件包目录执行（Windows 用系统 Python）：

命令用途
python maya_bridge.py --ping真投一条命令，返回 Maya 版本与当前场景
python maya_bridge.py --scan扫描各版本端口与备用段 7110~7129，列出在线实例
python maya_bridge.py --doctor只报告：谁在线、谁卡死、谁该清、有无渲染残留
python maya_bridge.py --doctor --kill-hung只清理「监听但不应答」的实例，健康实例不动
python maya_bridge.py --doctor --launch拉起 Maya 并等到真能应答
python maya_bridge.py <任务.py> --retry-if-crashed断连时自动体检、清理、拉起并重投一次；只用于幂等任务

指定版本或端口：--maya 2025、--port 7002，或设环境变量 SQUIRREL_MAYA_PORT。

资产索引与 AI

命令用途
python tools/asset_index.py --status本地查看索引条数、维度、模型与所属库
python tools/asset_index.py --verify一致性自检：尺寸、行号、id 映射
python tools/asset_index.py --doctor环境体检：Ollama、模型、索引与建议命令
python tools/asset_index.py --query "生锈的金属"语义检索验货
python tools/setup_semantic_env.py --all安装并验证 AI 依赖（Ollama、模型、索引）

插件内等价入口是「设置 → AI 设置 → AI 依赖检查」，报告落在 %TEMP%\squirrel_asset_manager\AI依赖检查报告.txt。

底座 HTTP 与命令

底座默认监听 127.0.0.1:39001（TCP）与 39002（HTTP），实际端口见 ~/.squirrel_asset_manager/broker_endpoint.json。

接口 / 命令用途
GET /health底座模式、在飞命令、实例与作业统计
GET /instances、GET /commands实例清单与命令清单（含 params_schema）
GET /jobs、GET /jobs/<job_id>作业列表与单条状态、结果、进度
GET /late_results超时命令的迟到结果邮箱
asset_semantic_status资产语义索引与模型状态
squirrel_ai_depsAI 依赖检查（先 status）
squirrel_maya_bridge底座视角的桥接探活（先 ping）

警告：--kill-hung 只清「监听但不应答」的实例。执行前先看 Maya 窗口，排除崩溃恢复、未保存或报错等模态框——点掉模态框可能救回未保存的场景。
