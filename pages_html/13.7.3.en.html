A crash inside renderer modules such as redshift-core-*.dll or vray_*.dll means the renderer itself crashed and took Maya with it; switch to out-of-process rendering and confirm the fix is actually in effect.

Symptoms

  • Maya disappears as soon as you render or use Update thumbnail → Render image.
  • The second render in the same process always crashes while the first one works.
  • The Windows event log shows the same DLL at the same fault offset.
  • A new MayaCrashLog*.dmp appears in %TEMP%, and after the crash the port may still be held by the crash reporter.

Steps

  1. Confirm the plug-in is upgraded to a build containing the Redshift blocking-render fix, then fully quit and restart Maya; a hot reload does not count.
  2. Do 2 to 4 thumbnail renders in a row and confirm it no longer crashes on the second.
  3. If it still crashes, set the environment variable SQUIRREL_MAYA_RENDER_VIA_EXE=1 to use out-of-process Render.exe. It is slower, but a renderer crash no longer takes Maya down.
  4. Check the Redshift version and license status; if the log shows a license error, fix the license first.
  5. Record the crash module name and offset with Event Viewer and keep the matching crash dump.
  6. Do not retry the same render path repeatedly inside one Maya process, which only produces more crash dumps.

Verify the result

Four thumbnail renders in a row all produce images, Maya stays open, and %TEMP% gains no new crash dump with the same signature.

If it still fails

  • Reproduce in a clean Maya instance or a minimal scene to see whether scene content is involved.
  • Collect the event log, crash dump, Redshift version and license status before reporting.
  • Temporarily switch to playblast or imported images for thumbnails so asset organization is not blocked.
  • Whether the AI per-frame render command also uses the blocking path is still unconfirmed; validate with a small batch before rendering at scale.
