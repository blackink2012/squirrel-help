If the category tree will not open, usually the library root is unreachable, the index cache is incompatible with the current code, or the category metadata is corrupted.

Symptoms

  • The sidebar stays on the loading placeholder, or is simply blank with no sub-libraries or categories.
  • Sub-library nodes exist, but sub-categories are empty, or the custom category disappeared.
  • The category tree does not refresh after switching asset libraries; only restarting the plug-in restores it.
  • The Script Editor shows [MaterialManager] 库路径无效 (invalid library path) or an incompatible index cache message.

Possible causes

CauseHow to tellAction
Library root is invalidThe path was moved or deleted, or a network drive is not connectedReselect an existing directory in the library list
No read permissionOpening the library directory is denied, or antivirus blocks itRestore read access and refresh
Index cache incompatible with the current versionThe log says "index cache incompatible, falling back to a full scan"Clear the cache and reload
Category metadata corruptedOne sub-library or category directory keeps failing to loadBack up the library, then rescan it separately or restore from backup
Sub-library/category changed in configurationconfig.json was edited but the UI did not changeRe-read the configuration
Folders added or renamed by hand were not syncedA directory exists on disk but not in the treeUse Sync categories from folder

Steps

  1. In the library list or settings, confirm the current library root exists, can be opened, and is not a disconnected network drive.
  2. In the AI assistant or command surface run library_health with op=status and check library_root, is_loaded, asset_count and category_count.
  3. If you suspect the cache, run op=clear_cache, then op=reload, so the plug-in rescans the disk.
  4. If you changed sub-library or category configuration, run op=reload_config, then refresh the UI.
  5. If you added category folders on disk by hand, use Sync categories from folder to bring them into the tree.
  6. After fixing permissions or paths, close and reopen the plug-in window.

Verify the result

The sidebar shows all sub-libraries and sub-categories, the asset counts match the number of .zasset folders on disk, and the grid refreshes when switching categories.

If it still fails

  • Check the [MaterialManager] log in the Script Editor to see whether the problem is the path, permissions, or a specific asset failing to load.
  • Back up the whole asset library before trying library_health op=reload; never hand-edit or delete category metadata files.
  • If only one sub-library is affected, switch to another library to confirm the plug-in itself is fine, then handle that sub-library separately.
  • Follow 6.3.3 "Library health anomalies" to read the load-failure list, or 6.8.2 "Diagnostic workflow" to collect information for a report.
