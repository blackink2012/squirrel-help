Filter the files in a source folder by extension and mirror them into a target folder with the full directory hierarchy preserved.

Purpose

Good for archiving assets, distributing textures and backing up a directory structure: pick only the formats you need while keeping the original hierarchy.

Input and output

  • Input: a source folder, a target folder and the list of extensions to copy.
  • Output: files rebuilt under the target folder with the source relative paths; with 「复制层级结构」 (Copy hierarchy) off they are flattened and name clashes get the parent folder name or a number.
  • Files already present at the target are skipped and never overwritten.

Steps

  1. Open 快捷工具 (Quick tools) → 批量镜像复制 (Batch mirror copy).
  2. Click 「浏览」 (Browse) next to the source folder and choose the source.
  3. Click 「浏览」 (Browse) next to the target folder and choose the destination.
  4. Fill the extensions under 「文件格式」 (File formats), comma separated; the default is .exr, .hdr, .png, .jpg, and a leading dot is optional.
  5. Optionally check 「仅预览（不实际复制）」 (Preview only, do not copy) and click 「开始复制」 (Start copy) to check the matches.
  6. Uncheck preview and click 「开始复制」 (Start copy) again.

Verify the result

  • Preview mode: the log ends with 「预览完成，共匹配 N 个文件」 (preview finished, N files matched) and nothing is written to disk.
  • Real copy: the progress bar completes and a summary appears (total / copied / skipped / failed).
  • The target directory shows the same relative paths as the source (when keeping hierarchy).

Options and notes

OptionDefaultNotes
File formats.exr, .hdr, .png, .jpgComma separated, case-insensitive, leading dots are added automatically
Preview only (do not copy)OffOnly counts and lists the files that would be copied
Copy hierarchyOnWhen off everything is flattened into the target root, with automatic name disambiguation
  • The source and target folders cannot be the same, otherwise the tool refuses to run.
  • Copying uses shutil.copy2 to preserve metadata such as modification times where possible.
  • A single failing file never aborts the whole run; failures with reasons are listed in the summary dialog afterwards.
  • Copying runs on a background thread so the interface stays responsive; with many files the "scanning files…" stage can take a while.
