One-line summary: the plug-in's own offline help site — clicking the Use help button at the far right of the toolbar opens a local web page with contents on the left, search on top and on-this-page navigation on the right.

It is a local web page, not online documentation: the plug-in starts a small HTTP service on this machine (127.0.0.1, ports 8790–8799) and opens it in the system browser. So it works offline and is fast. Besides keywords, search also uses local semantic retrieval (when the AI dependencies are installed).

How to open it

  1. The Use help button at the far right of the top toolbar (an icon button, tooltip "Use help");
  2. The browser opens the help home page at an address like http://127.0.0.1:8793/ (the port may differ).

Notes:

  • Clicking it again within the same plug-in process reuses the running service (the port does not change).
  • If no browser appears, look for [Help] opened help center: <url> in the Maya Script Editor and paste that URL into a browser manually.
  • When the help service cannot start it falls back to the legacy help page (Assets/help/help.html), which has fewer features.

Deep links: opening a specific page

The part after #/ in the address is the page id, so you can use:

  • http://127.0.0.1:8793/#/15.14.9 — open "Material conversion tool" directly;
  • http://127.0.0.1:8793/#/15.16.2 — open the menu item master index directly;
  • http://127.0.0.1:8793/#/12.1.1?cmd=hdr_to_zasset — open the command reference page and highlight that command (cmd= takes the command id).

The page id is the id in each page's frontmatter, and it matches the heading under each page title in this dictionary. The plug-in also supports calls such as open_help_center("8.14.9") with an id, which behave like deep links.

When search finds nothing (keyword tips)

  1. Speak plainly first, then use jargon. Search expands synonyms and many colloquial phrasings are already included (such as "font too small", "scale the UI", "model import", "material import", "missing textures", "crash", "frozen", "cannot find", "inaccurate search", "shortcuts", "semantic search"). Start with how you would normally say it.
  2. Use the exact UI wording. Help headings and bodies largely copy the interface text, so searching a button or menu name ("Quick tools", "Edit tags", "Update thumbnail", "License management") hits most often.
  3. Shorten the keywords. A long sentence is tokenized and all tokens must match, which easily yields nothing. Reduce "how do I batch convert HDR environment maps into assets" to "HDR to asset" or just "HDR".
  4. Try synonyms or switch languages. Search proper nouns directly (zmetal, mmap, mcp, dsh), or the other way round for Chinese names ("material conversion", "external AI tools").
  5. Read the mode note. If it always shows "lexical search · semantic temporarily unavailable", semantic retrieval is inactive (missing embedding dependency / index), so only keywords work; the fix is in 6.5.1.
  6. Fall back to contents and indexes. Browse chapters in the left contents, or go straight to 8.16.1 (find menus by task) and 8.16.2 (menu item master index).
  7. If a page fails to load ("page failed to load" / "run python tools/build_help.py at the project root"), the help data was never generated or is stale and must be rebuilt (a developer-side action; regular users can reinstall / update the plug-in).
