When a material becomes a flat color or black after import, usually the asset has no textures, the paths still point at the original machine, or fileTextureName was not rewritten successfully.

Symptoms

file node paths in the Hypershade show yellow / red or point at directories that do not exist; viewport materials have no pattern; a light asset's HDR / IES is not connected either.

Common causes

  1. Textures were not checked at export, so the .zasset has no textures/ at all.
  2. The import policy is 「源文件目录」 (source file directory), so paths are still the absolute paths of the export machine.
  3. The asset was moved or renamed and the original paths in meta.texture_map no longer work.
  4. Light textures / HDR / IES were not collected, or those files were deleted outside the asset.
  5. For multi-resolution textures only the currently selected resolution was imported and the others are missing.

Steps

  1. Open the .zasset and confirm the matching files really exist under textures/.
  2. Change the texture import policy in settings to copy into the project or the asset directory, then import again.
  3. Go back to the source scene, export again with textures checked, and avoid exporting material nodes alone.
  4. Read the Script Editor for logs such as 「贴图路径已解析」 (texture path resolved) or 「复制依赖失败」 (dependency copy failed) to locate the file.
  5. When only a few are missing, point file.fileTextureName back at the correct file in the attribute editor.

Verify the result

The file node paths point at existing files; the viewport shows the textures; the dome light's environment texture and an IES light's photometric profile work again.

If it still fails

  • Check whether meta.texture_map records "original path → textures/..."; without it the import side cannot match precisely.
  • Do not rename files inside textures/ by hand, or the relative paths inside .zmetal / .zlight no longer match.
  • When the asset's source files are gone, the only option is exporting again from the original project.
