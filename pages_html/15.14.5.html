一句话定位：选一批 .ma / .mb，写一段 MEL 或 Python，让它在每个文件里都跑一遍，可选跑完自动保存。

窗口标题叫「Maya批量脚本执行器」。它适合"同一件事要在几十个场景文件上做一遍"的活：批量改名、批量清空选择、批量补灯光、批量设置渲染参数……

从哪打开

入口具体怎么做
顶部工具栏「快捷工具」菜单「快捷工具」→「批量处理maya文件」
脚本浏览器「脚本浏览器」→ 添加插件目录下的 quicktools 目录 → 批量处理maya文件.py 双击运行

没有对应的命令入口（命令面里没有这个工具）。

界面上每个控件做什么

卡片「文件选择」

控件作用取值建议
「添加文件」加 .ma / .mb 到列表建议只加副本，见"风险"
「移除选中」把列表里选中的条目去掉（不删磁盘文件）—
「清空列表」清空整个待处理列表不删磁盘文件
「打开文件夹」在资源管理器里打开某个文件所在目录确认文件位置时用
「已选择 N 个文件」当前待处理数量开跑前再核一遍

卡片「脚本输入」

控件作用取值建议
单选「MEL」/「Python」这段脚本按哪种语言执行（默认 MEL）只选一个；两个都不选会提示"请至少选择一种脚本类型"
「MEL示例」/「Python示例」往编辑框里填一段示例脚本不知道怎么写时从示例改
「清空脚本」清空编辑框—
脚本文本框（占位「在此输入MEL或Python脚本...」）要跑的内容，带语法高亮先在「测试执行」里跑通它，再批量

卡片「执行选项」

控件作用取值建议
勾选「无头执行（mayapy 独立进程，不占用当前场景）」用 mayapy 起独立进程跑批，当前 Maya 与你打开的场景完全不受影响默认勾选，建议保持；取消勾选才会在当前 Maya 进程里逐个打开文件
勾选「执行后保存文件」勾 = 每个文件跑完就 save；不勾 = 只跑不存先不勾跑一遍看结果，确认了再勾上重跑
勾选「显示详细信息」日志里逐文件打印"处理文件 i/n"和"已保存"文件多时建议勾
勾选「高级选项」展开下面三个勾选项—
勾选「执行前备份文件」见"风险"：当前版本这一项不影响实际行为别依赖它，自己手动备份
勾选「强制保存（忽略警告）」同上，当前版本未接入执行流程同上
勾选「忽略错误继续执行」同上，当前版本未接入执行流程（实际行为一直是"出错记日志、继续下一个"）同上

底部按钮

按钮作用
「测试执行（当前场景）」只在当前打开的场景里跑一遍这段脚本，不打开文件、不保存。用来验证脚本对不对
「批量执行」对列表里每个文件：打开 → 跑脚本 →（勾了才保存）→ 下一个
「关闭」关窗口（跑批期间请别关）

卡片「执行日志」

控件作用
日志文本区逐文件结果、失败原因、最后汇总「成功: X 个文件 / 失败: Y 个文件」
「清空日志」清屏（不影响已跑的批）
「保存日志」把日志存成文件，出问题拿它去排查
「复制日志」复制到剪贴板
「就绪」状态行当前状态

一次完整的操作流程

  1. 先把要处理的文件复制一份（重要，见"风险"），只对副本操作；
  2. 快捷工具 →「批量处理maya文件」；
  3. 「添加文件」把这批副本加进来；
  4. 选 MEL 或 Python，写脚本；不会写就点「MEL示例」/「Python示例」在示例上改；
  5. 先点「测试执行（当前场景）」：它会在你当前正在看的场景里跑这段脚本 —— 所以先拿一个空场景或临时场景测；
  6. 测通了，取消勾选「执行后保存文件」，先点「批量执行」空跑一遍，看日志里有没有大面积失败；
  7. 确认没问题，勾上「执行后保存文件」，再点「批量执行」；
  8. 跑完看日志末尾的「成功 / 失败」统计；有失败就按文件名和错误原因逐个处理；
  9. 需要留档就点「保存日志」。

输出结果在哪

  • 脚本的效果直接落在每个 Maya 文件里（勾了「执行后保存文件」才会写回文件）；
  • 窗口里只产生日志：每条处理结果、失败原因、最终统计；
  • 批量跑完会自动尝试把原场景打开回来（它开始前记住了当前场景路径）；如果打开失败，日志里不会强调，但你的场景会停在这批的最后一个文件上 —— 这时不要随手保存。

风险与反悔（这一页最重要的一段）

  • 「批量执行」默认走「无头执行」（mayapy 独立进程），不占用当前 Maya；只有你取消勾选「无头执行」时，才会在当前 Maya 进程里逐个打开文件跑，那种情况下要注意：
    • 跑批期间当前场景会被顶掉（结束后会尝试打开回原场景）；
    • 当前场景如果有未保存改动，跑批前请先自己保存，否则可能丢；
    • 跑批期间不要动这个 Maya，等它跑完。
  • 「执行后保存文件」会直接覆盖磁盘上的源文件，没有版本、没有回收站。这就是必须先复制副本的原因：把要处理的文件复制到另一个目录，只对副本跑批，原文件永远不动。这一条是反悔的唯一可靠退路。
  • 三个高级勾选项（执行前备份 / 强制保存 / 忽略错误继续执行）在当前版本里没有接到执行流程上，别把安全交给它们。实际行为固定是：单个文件出错 → 记日志 → 继续下一个。
  • 脚本本身的风险仍然存在：脚本写错会在批里连续错几十次。所以第 5 步「测试执行」一定要做。
  • 反悔：原文件没动 → 直接重来；副本被改坏了 → 从备份再拷一份。
