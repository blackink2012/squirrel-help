A disconnect usually is not a broken plug-in: Maya has exited, the bridge port is closed, the port moved to the backup range, or the main thread is held by a modal dialog or a long command.

Symptoms

  • The standalone edition reports no online Maya, or a call returns maya_offline / port_closed.
  • --ping cannot connect, or connects but never gets a reply.
  • An asset cannot be imported although Maya is online, or it lands in another Maya.

Causes and fixes

  1. Look at the Maya window first: with a crash-recovery, unsaved-changes or error dialog present, dismiss it and retry the read-only query. A modal dialog holds the main thread and looks exactly like a hang.
  2. Run python maya_bridge.py --doctor to see who is online, who listens without answering and whether render leftovers exist.
  3. If only the port changed, use --scan to find the actual port and then connect with --maya version or --port port; setting SQUIRREL_MAYA_PORT also works.
  4. If the port is closed, check 「允许外部工具连接 Maya（独立版 / 命令行）」 (allow external tools to connect to Maya) in settings, or run cmds.commandPort(...) inside Maya.
  5. Once it is confirmed to be a hang (not a dialog), use python maya_bridge.py --doctor --kill-hung to clear only instances that listen but do not answer.
  6. With no usable instance use python maya_bridge.py --doctor --launch, which starts Maya and waits until it really answers.
  7. Idempotent tasks can add --retry-if-crashed to clean up, launch and resubmit once; a task file containing SQ_DESTRUCTIVE = True is refused.

Verify the result

--ping returns version | scene again, --doctor marks the target port healthy, and the standalone toolbar's target tooltip shows the expected scene.

Tips and warnings

  • Self-healing only suits idempotent or read-only tasks. A crash loses the unsaved scene, and a resubmit only reruns the task itself, never restoring the original session state.
  • There is no resident supervisor process, so Maya is not started automatically when nobody is running a task.
  • Every self-healing attempt appends a record to ~/.squirrel_asset_manager/bridge_recover.log.
