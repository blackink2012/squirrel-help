First decide whether "nothing was found" or "the ranking is wrong": the former is usually an index or metadata problem, the latter usually a description that is too broad or a wrong scope.

Symptoms and causes

  • A freshly added asset is not found: the index lags. The next search syncs incrementally, or run python tools\asset_index.py --sync.
  • Similar assets do not rank first: the name, tags and notes are too sparse, or there is no appearance description. The index text comes mainly from those fields.
  • Several concepts blur together: one sentence mixes material, purpose and color and the semantics average out. Split it into two or three sentences, or use keyword mode.
  • Wrong scope: a category is selected although you think you are searching the whole library; clear the category selection and retry.
  • Everything is scrambled after changing models: the index and the current model differ, so it was judged unavailable and fell back to lexical.
  • HDR assets are hard to tell apart: their thumbnails are all light-probe previews, which any retrieval struggles with; add scene or light-source tags manually.

Steps

  1. Check asset_semantic_status and confirm it is available with index_lag.stale false.
  2. Add names, tags and notes to key assets; for assets with sparse metadata, generate an appearance description with a description tool first.
  3. Shorten the query and keep only the most important material or appearance words.
  4. Search within the right category, or switch to "search by image".
  5. When it is still inaccurate use mode="keyword" to verify whether the semantic path introduced the bias.

If it still fails

Record the original query, the expected asset name and the actual top results; that is the key evidence for telling index quality from metadata quality.
