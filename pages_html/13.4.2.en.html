Missing textures or dependencies usually mean files were not collected during packing, or that after import the paths still point at the author's machine or a temporary directory.

Symptoms

  • After import the material turns black or pink, or the viewport shows a checkerboard.
  • A file node's texture path points at a drive letter or author directory that does not exist.
  • Proxies, caches, ABC or USD references are missing and only an empty group remains.
  • Only some textures of one asset are lost while others are fine.

Possible causes

CauseHow to tellAction
Associated files were not collected on exporttextures/ or deps/ is missing from the asset directoryTick collect associated files when exporting
Textures originally lived outside the projectPaths point at external directories such as X:/Megascans/...Move the source files somewhere reachable and export again
A .zasset was copied by hand and is incompleteThe directory holds clearly fewer filesDelete it and re-obtain it through the library copy/import workflow
Relative paths break after importThe texture file names exist but the base path is wrongRe-import the asset so paths resolve against the asset directory
Proxy type does not matchThe cache/proxy node type differs from the rendererConfirm the node for V-Ray, Redshift or USD
Permission or network drive issueThe file exists but cannot be readRestore permissions, or copy the asset to a local drive first

Steps

  1. Open the .zasset and confirm the files really exist under textures/ and deps/.
  2. On the export side, tick Collect associated files again and confirm the source textures, caches and proxies are accessible.
  3. Use a dependency scan to see the missing count and exact paths; fill in the source files before exporting again.
  4. Delete the hollow or incomplete asset and import it again from the library; never copy half a directory by hand.
  5. For proxy assets, make sure the object is connected to the right node before collecting: V-Ray, Redshift and USD each have their own proxy node type.
  6. If paths still point at the author's machine after import, confirm the texture files are inside the asset directory and trigger a path rewrite once more.

Verify the result

Every file node path in the material exists, the viewport renders correctly, and the dependency scan reports zero missing files.

If it still fails

  • Use Maya's File Path Editor to see which textures are still broken, and record the file names and expected directories.
  • If only proxies or caches are missing, confirm the corresponding node really existed at export time instead of an empty group.
  • Locate the problem further with 4.1.12.3 "Dependency scan" and 4.2.7.2 "Missing dependencies".
  • When reporting, include the missing file list, the asset directory structure and the "missing N" line from the export log.
