One-line summary: the middle four blocks of the right column govern which formats materials / nodes are stored in and which formats geometry is stored in.

Block one: export options (material only)

ControlTypeEffectSuggested valueWhat filling it in wrongly does
Material only (skip geometry / proxies)CheckboxStores only the material network and skips geometry and proxies; even with .ma/.mb ticked only material nodes are writtenTick it when you want materials without geometryOnce ticked, a model asset becomes a "materials only" package and imports yield no model

When ticked: geometry formats (.fbx/.obj/.usd and so on) are skipped internally even if ticked, and .ma/.mb are still exported but hold the material node network instead of the model. 4.3.2.7 has the full description.

Block two: material formats / light formats / node formats

The block title follows the category and it holds three items:

ControlTypeEffectSuggested valueWhat filling it in wrongly does
Material preset .zmetal (materials) / light preset .zlight (lights) / node preset .zmetal (others)CheckboxExports the material / light / node network into the plug-in's own preset format so the node network can be restored exactly on importAlways tick it for materials and lightsOff: the asset holds no material data and importing gives only geometry or a shell
Write all materials into one .zmetalCheckbox (indented, shown only when .zmetal is ticked)Merges several materials into a single .zmetalTick it when one asset holds the several materials of one objectOff: each material gets its own .zmetal file and import picks as needed
Material mapping .mcm (N materials detected)CheckboxWrites an extra "material → model" table so import can put materials back onto the right modelTick it when the asset carries a model with several materials (ticked by default)Off: a multi-material model may only be matched by name on import and easily ends up wrong

Light assets have no .mcm row (lights have no material mapping) and no "write all materials into one".

Block three: geometry formats (through Maya's native export)

ControlTypeEffectSuggested valueWhat filling it in wrongly does

Maya Binary .mbCheckboxExports in Maya's binary format, smaller and fasterFor large scenes used only locally or in the same Maya versionSlightly worse cross-version compatibility

USD .usdCheckboxUniversal scene descriptionTick it when the pipeline uses USDNeeds Maya's USD plug-in (a status of "not loaded / unavailable" means it cannot export)

Why some formats are gray

Formats that do not apply to the current category are gray and cannot enter the export configuration, with the tooltip "this format does not apply to the current category and is locked (adjust in Settings → Export defaults)". The built-in locking rules:

CategoryFormats locked by default
Materials / lightsFBX, OBJ, USD, Alembic and every proxy format (such assets have no geometry)
Textures / HDR / images / audio / animation dataAlmost all node and geometry formats (they are files or pure transform data)

To change a lock: unlock that format on the Export defaults page (see 8.9.4).

The asset has geometry but no material.zmetal was not tickedRe-export with it ticked, or add it with Update asset → Append format
