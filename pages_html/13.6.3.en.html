Large batch operations should use batch interfaces or async jobs, and after a timeout you should check the result first instead of rerunning immediately.

Symptoms

  • Progress does not move for a long time during batch import, export or thumbnail generation.
  • The operation timed out, and you are not sure whether the background work is still running.
  • The same batch ran twice, producing duplicate assets or files.
  • One failing asset stalls the whole batch, or the batch results are incomplete.

Possible causes

CauseHow to tellAction
Items processed one by one instead of in batchThe log handles one item at a time and time grows linearlyUse batch commands or multi-select operations
Thumbnails rendered sequentially in the main processThe Maya UI is occupied and CPU/memory keep risingSwitch to headless offscreen batch generation
One bad asset blocks the batchThe log stops at the same assetIsolate the problem asset, then rerun the rest
Resubmitted after a timeoutDuplicate results appear for the same batchCheck the result of the submitted job before rerunning
The output directory is on a network driveWrites are slow or fail on permissionsWrite to a local disk first, then copy
The batch is too largeMemory and handles keep growingSplit into smaller batches and verify each one

Steps

  1. Test with 5 to 10 assets first to confirm the workflow, naming and output directory.
  2. For thumbnail generation use Update thumbnail → Background render (headless), which runs in a separate mayapy process and does not occupy the current scene.
  3. Split export and import by sub-library or category; avoid processing an entire library at once.
  4. After submitting an async task, record its job_id and check progress and cancellation interfaces instead of waiting with sleep.
  5. After a timeout, check late results and job history first and retry only once you confirm nothing completed.
  6. Never rerun a destructive operation just because of one timeout; work through the failure list item by item instead of starting the batch over.

Verify the result

Batch progress advances normally to completion, the failure list is clear, the asset count matches expectations and no duplicate files exist.

If it still fails

  • Record the batch size, start and end times, failing entries and their logs.
  • Run the failing assets separately to see whether it is one asset or the batch scale.
  • Check the output directory's free space, permissions and network connection.
  • Confirm job status per 5.2.4 "Async, progress and cancellation" before deciding to rerun.
