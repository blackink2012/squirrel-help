A hollow asset is a .zasset that contains only meta.json and a thumbnail, with formats listing only sicon or aicon and no geometry, material or textures.

Symptoms

  • The asset can be found in the grid, but importing it adds no objects to the scene.
  • Opening the .zasset directory shows only meta.json and thumb.sicon.
  • formats in meta.json lists only sicon/aicon, where it should include ma, mb, zmetal or textures.
  • The asset creation result has status ok, but notes mentions that one format failed to export.

Possible causes

CauseHow to tellAction
The scene holds unknown data that blocks saving .manotes says "this file contains unknown data"Tick .mb, or let the tool fall back automatically
A geometry format is ticked but the selected objects have no shapeThe log says no exportable objects were foundSelect models with meshes, not empty groups
Only textures, or only materials, are tickedAll geometry formats are off in the presetTick at least one geometry format, or confirm the asset type
The export error was swallowed by an older buildThe old build still reports successUpgrade to a build with the geometry self-check and .mb fallback
The target directory is not writableThe export log shows a permission errorRestore directory permissions and export again
The asset was damaged by handMetadata or directory structure is incompleteDelete and recreate it; never assemble a .zasset by hand

Steps

  1. Open meta.json and confirm whether formats contains the expected formats.
  2. Back in Maya, confirm the selected objects really have meshes or materials, not just empty transforms.
  3. When recreating the asset, tick at least one geometry format; for material assets also tick the material preset and textures.
  4. If notes says .ma failed because of unknown data, tick .mb instead; newer builds fall back automatically when .ma fails.
  5. After export, check formats again to confirm the geometry files were really written.
  6. Once you confirm it is hollow, back it up, delete the old asset and recreate it with the fixed workflow.

Verify the result

formats contains geometry, material or texture formats, and importing into the scene produces the matching objects or materials instead of an empty group.

If it still fails

  • Retry in a new empty scene containing only the target objects to rule out unknown nodes and third-party plug-ins.
  • Use cmds.unknownPlugin(q=True, list=True) to check whether the scene carries unknown plug-in data.
  • Export with only .mb ticked first to confirm the geometry itself is writable, then add other formats back one at a time.
  • Check with 6.3.3 "Library health anomalies" whether the asset is recorded as a load failure, and report the original notes text.
