After a crash, follow three steps — diagnose, then clean hung instances or dismiss modal dialogs, then launch and prove it answers. Do not reopen repeatedly or kill processes outright.

Symptoms

  • Maya suddenly disappears, goes white, or stops responding for a long time.
  • The tool reports a disconnect, and reopening Maya still cannot connect.
  • After a new Maya starts, the client reports a port already in use or a refused connection.
  • The unsaved scene from before the crash cannot be found.

Possible causes

CauseHow to tellAction
The Maya process already crashedThe process is gone and %TEMP% has a new crash dumpRecover with the three steps
The main thread is hungThe process exists and the port listens, but nothing answersConfirm, then clean the hung instance
A modal dialog blocks itThe Maya window shows a recovery, error or unsaved promptDismiss the dialog first
An old instance holds the default portThe new instance fell back to 7110–7129Scan the fallback range and connect to the actual port
The renderer or a plug-in took Maya downThe event log points at a renderer DLLSee 6.7.3 "Renderer crash"
The unsaved scene is lostThe autosave directory is empty or autosave was offSee 6.7.4 "Autosave and recovery"

Steps

  1. Diagnose: run python maya_bridge.py --doctor. It only reports who is online, who is hung and what should be cleaned.
  2. Look at the Maya window first; dismiss any modal dialog and run --doctor again. Once you confirm it is hung rather than a dialog, run python maya_bridge.py --doctor --kill-hung.
  3. Launch: run python maya_bridge.py --doctor --launch, which waits until Maya really answers instead of just checking that the process started.
  4. Confirm at the end: run python maya_bridge.py --ping or --scan to confirm the version, scene and actual port.
  5. If a task must be resubmitted, only use --retry-if-crashed for idempotent or read-only tasks; when the task file declares SQ_DESTRUCTIVE = True, the tool refuses to resubmit automatically.
  6. To recover unsaved content, check the autosave directory and %TEMP%\squirrel_pre_render\; copy the files out before opening them.

Verify the result

--doctor reports a usable healthy_port, --ping returns the Maya version and current scene, and new tasks run normally.

If it still fails

  • Do not keep launching more Maya instances; first check whether the old instance still holds the port.
  • Check ~\.squirrel_asset_manager\bridge_port.log and bridge_recover.log for port changes and self-heal records.
  • For crash forensics, check the Windows event log (module name + offset) and %TEMP%\MayaCrashLog*.dmp.
  • Never rerun destructive tasks just because of one disconnect; check late results and job history first.
