The current version has no one-click multi-machine sync. To keep several computers consistent, share the asset library and maintain local configuration and licensing on each machine.

What it does

This page helps you decide what can be shared and what must be handled per machine, so you do not treat the configuration directory as a sync drive.

What can be shared and what must stay separate

ItemShared with the libraryNotes
Asset files and category foldersYesPut the asset library on a network or sync drive and point each machine at the same path in settings
Plug-in presets Assets/preset/*.jsonManual copyThey live in the plug-in install directory and do not sync automatically; overwrite them with backup files
app_settings.jsonNoIt lives in ~/.squirrel_asset_manager/ on each machine and holds the library list, UI preferences and AI keys
LicenseNoLicensing is bound to the machine, so each computer must be activated separately
Semantic indexShared by default (separated per backend)By default it lives inside the library in `.squirrel_ai_index\<official\ollama>: vectors from the two backends are not interchangeable, each uses its own subfolder and they do not overwrite each other. Concurrent writes from multiple machines on the same backend are still not coordinated, so you can point ai_asset_index_dir` to a per-machine local folder
Library lockNoThe lock only applies inside one plug-in process; multiple machines writing the same library at once are not coordinated

Steps

  1. On each machine, add the same shared asset library path in settings and make it the default.
  2. Activate the license separately on every machine.
  3. When the context menu, double-click commands and export defaults must match, copy the corresponding preset JSON from one machine to the others.
  4. Set a local ai_asset_index_dir on each machine so the indexes do not overwrite each other.
  5. Agree that only one machine writes to the library at a time, or coordinate concurrency manually.

Verify the result

Every machine opens the same asset library and sees the same categories and assets, and each shows a licensed state.

Tips

  • Do not copy app_settings.json straight onto another machine: its absolute library paths and AI keys are machine-specific.
  • Several machines writing the library simultaneously can conflict; see Library lock and concurrency.
  • There is currently no formal configuration sync feature: the settings window has no such switch, so multi-machine consistency depends on copying preset files by hand.
