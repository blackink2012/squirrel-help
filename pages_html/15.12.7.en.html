One-line summary: when the plug-in starts separate mayapy / kick processes to render, this small non-modal window lets you keep working while watching which item is running, which stage it is in, and what was just rendered.

The window is titled Background render · progress.

When it appears

JobUses this window
Background thumbnail rendering (right-click Update thumbnail ▶ Background render)Yes, rendering jobs use it
Format conversion (right-click Format conversion)No; it uses a modal progress dialog (8.12.4)

The window is non-modal and stays on top: it does not block you and does not steal focus; closing it does not stop the job.

What the window contains

AreaContentDescription
Title line"Preparing…" → "Asset 1/5: <name>"Shows preparing until processing starts
Stage line"Stage: <stage name>"Which step is running (building, applying materials, rendering, writing back and so on)
Progress bar0% → 100% with a percentageIt advances per asset, not per rendered frame
Counter line"Done 3/5"Same source as the progress bar
Preview cardA 256×256 square preview showing "(nothing rendered yet)" when emptyTakes the newest PNG in the job directory
Render note"Latest image: <file name>"The file name behind the preview card
CancelRed danger buttonThe only way to stop, see below
CloseSecondary buttonOnly closes the window; the job keeps running

What happens on completion

  1. The progress bar fills and the title line becomes "Job finished".
  2. The stage line clears and the counter becomes "N succeeded · M failed · K skipped".
  3. Cancel turns gray and unclickable.
  4. The window closes itself after about 2 seconds — that delay lets you look at the last thumbnail.
  5. The job also produces a summary dialog (success / failure / skipped details), so nothing is lost when the window closes.

What cancelling means

  • After clicking Cancel the stage line immediately reads "Cancelling (waiting for the current asset to finish)…" and the button turns gray.
  • This is cooperative cancellation: the asset currently being processed finishes first, then the whole job stops.
  • Images already rendered are kept and are never rolled back.
  • On Windows the cancel kills the whole process tree (mayapy plus the kick and other child processes it started) so no zombie renderer is left behind.

A complete example

  1. Right-click an asset → Update thumbnail ▶ → Background render → choose the settings → Start generating.
  2. The progress window appears with "Preparing…".
  3. It runs "Asset 1/3" with the stage line showing the current step.
  4. The first image appears in the preview card.
  5. If the settings were wrong (the wrong renderer, for example) click Cancel and wait for "Cancelling…" to finish.
  6. When everything is done the window closes itself after 2 seconds; reopen it with the correct settings if needed.

Common questions

QuestionExplanation
Does closing the window stop rendering?No. Closing only stops watching; you must click Cancel to stop the job
Why does the progress bar advance per asset?The job queues assets and produces one image per asset; the internal frame progress of a single render is not reflected on that bar
The preview card stays on "(nothing rendered yet)"?The first image has not been written yet, or rendering failed (the counter shows failures when the job ends)
Why did the window close by itself?It closes about 2 seconds after completion, by design
Why is there no such window for format conversion?Format conversion uses a modal progress dialog and is not a rendering job
