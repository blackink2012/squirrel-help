Semantic search is an optional enhancement. When it is unavailable, search falls back to lexical matching automatically and never stops working entirely.

Symptoms

  • Search still returns results but matches literally only, so colloquial descriptions miss the target asset.
  • The status shows available=false with a reason such as "no index", "cannot reach Ollama" or "circuit breaker".
  • The first search is noticeably slow and then normal again for a while, or semantic search stays unavailable.
  • The index was built already, but it stopped working after the model changed in settings or environment variables.

Possible causes

CauseHow to tellAction
The ai_asset_semantic setting is offai_asset_semantic is false in app_settings.json, and the reason says it was turned off in settingsSet it back to true (the settings UI has no switch for this; edit the config file or use the command settings_set)

Ollama is not installed or not runningThe status says the service cannot be reachedInstall and start Ollama
The embedding model is not pulledollama list does not show the modelPull embeddinggemma-2:740m
A recent failed call tripped the circuit breakerThe status reports a cooldown in secondsWait for the cooldown, or set the cooldown environment variable to 0 to retry immediately
The model from environment variables does not match the indexThe status reports a model mismatchRemove the environment variable, or rebuild with that model
The host lacks numpyA notice says it still works but recall is narrowInstall numpy, or accept degraded results
The index lives on a shared or synced driveSeveral machines write the same backend index concurrentlyMove the index to a local directory (different backends are already split into official/ollama and do not overwrite each other)

Steps

  1. Open Settings → AI and run an AI dependency check to confirm the state of Ollama and the embedding model.
  2. In a terminal run ollama list to confirm the service is running and the model is pulled; if missing, run ollama pull embeddinggemma-2:740m.
  3. Confirm the semantic search master switch is not off: it maps to the config key ai_asset_semantic (on by default), and the settings UI currently has no switch for it — edit ~/.squirrel_asset_manager/app_settings.json, or have the AI assistant run settings_set(updates={"ai_asset_semantic": true}) (that command is high risk and asks for confirmation first). The same group also has ai_asset_semantic_sync (on by default; when off, it only builds once if no index exists).
  4. When the asset index is missing or damaged, run python tools/asset_index.py --sync; use --rebuild for a full rebuild.
  5. Check whether environment variables such as SQUIRREL_EMBED_MODEL are set; never let the query model differ from the index model.
  6. After moving the index to a local disk, reopen the plug-in window so the setting takes effect, then search again.

Verify the result

asset_semantic_status returns available=true, the match field shows semantic or both, and colloquial queries hit the target asset.

If it still fails

  • Use mode=keyword to keep search usable while you investigate the semantic chain separately.
  • Read reason and index_dir from asset_semantic_status to see whether the index, the model or the service is missing.
  • The first query may exceed the 20-second timeout while the model cold-starts; try again afterwards, since queries are much faster once the model stays resident.
  • Continue with 4.5.9.1 "AI unavailable" and 4.8.4.1 "AI dependency check and install".
