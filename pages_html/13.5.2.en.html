The asset library index and the Maya documentation index are two independent datasets; rebuild whichever one is missing. If you switch the embedding model, you must rebuild.

Symptoms

  • A notice says there is no asset library semantic index yet, or that kb/semantic/meta.json is missing.
  • The index directory exists but is missing vectors.i8, scales.f32 or meta.json.
  • The status says the index model differs from the expected model, or that the index directory belongs to another asset library.
  • After changing models, search suddenly falls back to lexical matching, or results get clearly worse.

Steps

  1. Run asset_semantic_status and record dir, model, count, reason and index_dir.
  2. When the asset library index is missing, run python tools/asset_index.py --rebuild; use --sync when you only want to catch up with newly added assets.
  3. When the Maya documentation index is missing, run python tools/build_semantic_index.py --model embeddinggemma-2:740m.
  4. When the model is not pulled, run ollama pull embeddinggemma-2:740m first, then rebuild.
  5. If you set an index root directory, confirm it is on a local disk; each library automatically uses its own subdirectory under that root.
  6. When told the index belongs to another library, either clear the directory override and rebuild, or confirm the original library no longer uses it and let the new one take over.

Verify the result

asset_semantic_status shows an index count greater than 0, model matches the index record, and search no longer reports a missing index.

If it still fails

  • Confirm the model name in meta.json exactly matches the pulled model, including the tag.
  • Back up the index directory before deleting it; if a rebuild fails, keep meta.json and the error message.
  • Verify the documentation index with maya_docs(action="status", probe=true) or tools/setup_semantic_env.py --all.
  • Follow 4.5.6.5 "Rebuild and model selection" for the correct procedure after switching models.
