导入后发现贴图变粉、变黑，或资产里没有 textures/、deps/，先确认导出时文件是否真的被打包。

症状

  • 导入资产后材质显示粉色/黑色，贴图节点指向空路径。
  • .zasset 里没有 textures/，或 deps/ 下缺少对应缓存、代理、引用文件。
  • meta.json 的 dependencies_missing 不为空，导出日志出现「依赖缺失」。

常见原因

原因判断方法处理
导出时贴图路径已经断开Maya 里 file 节点的路径不存在先用 File Path Editor 重新定位贴图，再导出
没有勾「贴图 textures/」资产内没有 textures/重新导出并保留该复选框
没有勾「收集关联文件」缓存/代理/引用没进 deps/勾选后重新导出
依赖在收集范围之外dependencies_out_of_scope 有记录把依赖放到本地可访问路径，或随资产手动交付
路径含无法解析的记号dependencies_unresolved_tokens 有记录把路径展开为实际文件路径后重导
引用文件未加载引用节点状态为未加载先在 Maya 中加载引用，再导出或收集

解决步骤

  1. 在 Maya 中检查选中物体的 file、aiImage 等贴图节点，确认路径指向真实文件。
  2. 重新导出时保留 贴图 textures/；有缓存、代理或引用时勾选「收集场景中已挂载的缓存/代理/引用文件」。
  3. 导出后检查 .zasset/textures/ 和 .zasset/deps/ 是否出现对应文件。
  4. 打开 meta.json，查看 texture_map、dependencies_missing、dependencies_out_of_scope、dependencies_unresolved_tokens。
  5. 导入时使用资产自带的导入入口，程序会按 texture_map 把原路径重映射到包内路径。

仍不行怎么办

  • 搜索 Script Editor 里的 [StageTextures]、[Export] 依赖、[Export] 依赖警告，确认是收集失败还是路径本身断开。
  • 换一台机器验证：若对方能看到贴图，说明缺失发生在原机器的路径，而不是资产结构。
  • .ma 文件里保留的是导出时的原始绝对贴图路径，不能只凭 .ma 文本判断资产是否缺图；以 textures/ 和 texture_map 为准。
