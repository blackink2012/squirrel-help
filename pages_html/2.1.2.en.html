Spending two minutes on the items below avoids the three usual problems: failed overwrite, lost settings, and an installation that will not start.

Steps

  1. Confirm the package type: release builds do not have test in the file name.
  2. Verify the installer: compare the hash as described in "Installer and SHA256 verification" to confirm the download is complete.
  3. Close Maya.
  4. Note the current version: write down the old version number so you can find the matching installer when rolling back.
  5. Back up settings and the asset library: copy ~/.squirrel_asset_manager/app_settings.json and the library directory; uninstalling does not back them up for you.
  6. Check for old copies: look for a squirrel_asset_manager copy left by a historical install in each version's scripts directory (older script installs put it under %MAYA_APP_DIR%\squirrel_asset_manager) and clean it up when the installer prompts.
  7. Confirm the ports are free: driving Maya from the standalone edition needs ports starting at 127.0.0.1:7001; a second instance of the same Maya version uses the backup range 7110–7129.
  8. Prepare license information: online activation needs an activation code; offline activation needs the machine code and a license file.

Verify the result

  • All Maya instances are closed and the plug-in directory is writable.
  • Settings and the asset library have usable backup copies.
  • The activation method is decided (online or offline).

Common failures

  • Uninstalling without a backup: the asset library is usually kept, but custom settings may be reset.
  • Maya still running: overwriting .pyd files fails with "access denied".
  • Wrong build: a test build distributed as a release build, containing documents that must not be published.
