The plug-in has three ways to drive Maya, differing only in whose scene is touched and how to iterate: headless mayapy, the bridge command channel and the in-Maya Script Editor.

The three paths

PathFormAffects the current sceneBest for
mayapy standaloneSeparate process, full Maya core, no interfaceNot at allRecomputing from scratch, batch thumbnails, batch conversion
Bridge command channelDrives a running Maya through commandPortYesReading and writing the scene the user has open
Maya Script EditorThe user runs it manuallyYesOne-off scripts, handing a script to the user

How to choose

  • Recompute from scratch → mayapy. It works in its own empty scene and cannot see the user's window or viewport.
  • Modify the user's copy → the bridge command channel. Reading the current selection, current frame or current viewport requires this route.
  • Long jobs (rendering, exporting, large imports) → run them as async commands and watch progress instead of blocking the main thread.

Boundaries and cautions

  • The standalone edition needs an online Maya for scene operations; browsing assets, searching and file-level work can happen offline.
  • Many functions in core/ and integration/ self-degrade through a module-level _IN_MAYA, so calling them directly in a separate process does nothing and reports no error. Any call that would hit such an early return must go through a remote channel.
  • The two channels are separate processes that cannot see each other; seeing no interface activity while using mayapy is normal.
