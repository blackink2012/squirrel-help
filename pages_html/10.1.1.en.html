The plug-in drives a running Maya through Maya's native commandPort, and the connection only uses the loopback address 127.0.0.1, so Maya is never exposed to the LAN.

Prerequisites

  • Maya is running and its version is supported by the plug-in.
  • 「允许外部工具连接 Maya（独立版 / 命令行）」 (allow external tools to connect to Maya, standalone / command line) is checked in settings. The matching option is bridge_auto_port, on by default, written into each version's userSetup.py startup block at install time.

Port rules

Default ports count down by year: port = 7001 + (2026 - version year).

Maya20262025202420232022
Port70017002700370047005

When a second instance of the same version starts, the default port is taken by the first one, so the later instance uses the backup range 7110~7129; see "Backup ports and auto-discovery".

Steps

  1. Start the target Maya and confirm the option above is enabled in settings.
  2. In the project root run python maya_bridge.py --ping and confirm a reply arrives.
  3. To see which versions are online run python maya_bridge.py --scan.
  4. To open the port manually, run this in Maya's Script Editor (Python tab):
import maya.cmds as cmds
cmds.commandPort(name="127.0.0.1:7001", sourceType="python")

Verify the result

--ping returns a string like 2026 | <untitled>, the first part being the Maya version and the second the current scene; --scan lists the online state of every port.

Tips and warnings

  • The channel is eval mode: it evaluates a single-line expression and returns its value; print output only goes to the Maya Script Editor and never back to the caller.
  • Never call the bridge client from inside the Maya process: it would connect to itself and block the main thread, and the code has an explicit deadlock guard for that.
  • To pin a target, set the SQUIRREL_MAYA_PORT environment variable, or use --maya 2025 / --port 7002.
