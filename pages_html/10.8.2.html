Maya 崩溃后，端口往往仍显示 LISTENING，但那通常是残留进程或崩溃报告器；恢复要先体检，再决定清理还是拉起。

症状

  • Maya 窗口消失，或重启后客户端仍报连不上。
  • netstat 显示端口在监听，但 --ping 被拒或超时。
  • 新启动的 Maya 跑到了 7110 而不是默认的 7001。
  • %TEMP% 下出现新的 MayaCrashLog<日期>.<时间>.dmp。

解决步骤

  1. 先看 Maya 窗口：如果是崩溃恢复、未保存提示这类模态框，点掉它可以救回未保存场景，不要急着杀进程。
  2. 执行 python maya_bridge.py --doctor，查看每个端口的监听、应答、PID 与判定。
  3. 确认是「监听但不应答」后，执行 python maya_bridge.py --doctor --kill-hung，只清卡死实例，健康实例不动。
  4. 没有可用实例时执行 python maya_bridge.py --doctor --launch，它会拉起 Maya 并等到真能应答。
  5. 收尾用 --scan / --ping 确认在线的版本与场景；客户端只认某端口时设 SQUIRREL_MAYA_PORT=7110。
  6. 根据 --doctor 列出的渲染残留进程（mayabatch / Render / kick / oiiotool）确认是否需要结束。

结果验证

--ping 返回 版本 | 场景，--doctor 中目标端口判定为 healthy，且没有新增崩溃转储。

提示与警告

  • 目前没有常驻监督进程，不会在没人跑任务时自动拉起 Maya。
  • --retry-if-crashed 只对幂等 / 只读任务可用；任务声明 SQ_DESTRUCTIVE = True 时会被拒绝重投。
  • 自动保存只保护已存过盘的场景；程序驱动、无人工交互时是否落盘尚未验证，重要场景请先手动保存。
