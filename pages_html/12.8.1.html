出问题先看三处：Maya Script Editor 的实时 traceback、~/.squirrel_asset_manager/ 下的桥接日志，以及 dsh_home 下的底座与审计记录。

用户目录

~/.squirrel_asset_manager/（Windows 为 C:\Users\<用户名>\.squirrel_asset_manager\）：

文件内容
app_settings.json个人设置；损坏时会重命名为 .bak 或 .corrupt_<时间戳>
bridge_port.logcommandPort 开端口结果；默认端口被占、退到 7110~7129 时也记在这里
bridge_recover.log--retry-if-crashed 的自愈记录：断连原因、清理、拉起与重投端口
broker_boot.logMaya 启动时自动注册到底座的成败原因
broker_endpoint.json底座实际 TCP/HTTP 端口；客户端据此改连
help_cache/maya_docs 在线兜底的目录树与页面缓存

dsh 运行期目录

默认 <插件包>/dsh_home/，可用 SQUIRREL_DSH_HOME 或 DSH_HOME 覆盖：

文件/目录内容
broker_daemon.log独立底座进程的输出；起不来的原因基本都在这里
ai_jobs.jsonl异步作业历史，含状态、结果与最终进度
audit.jsonl每次命令调用一条：命令、参数、风险级别、会话、实例与结果摘要
dsh_install.logdsh 运行时安装日志
squirrel_web_<实例>.logdsh Web 前端启动输出
sessions/、storages/会话与存储；坏会话会挪进 quarantine/，改名不删除
skills/落位后的技能束

临时目录

路径内容
%TEMP%\squirrel_asset_manager\AI依赖检查报告.txtAI 依赖体检报告
%TEMP%\squirrel_asset_manager\ai_install.log一键安装 AI 依赖的完整日志
%TEMP%\squirrel_standalone_host.log独立版挂载宿主的输出
%TEMP%\squirrel_jobs.jsonl独立底座未指定作业文件时的默认历史
%TEMP%\MayaCrashLog<yyyymmdd>.<hhmm>.dmpMaya 崩溃转储

界面内日志

  • Maya Script Editor 显示插件 traceback 与 print 输出。
  • 批量处理、批量镜像复制等快捷工具在自己的日志面板里显示过程，部分支持另存为文本。

提示：崩溃取证可同时看 Windows 事件日志里的「错误模块名称 + 错误偏移」、上述 .dmp 与桥接日志；若崩在渲染器自己的 dll，优先改走进程外渲染。
