The embedding model defines the vector space; when the model, dimensions or text template change, the old index must be rebuilt or it can only be judged unavailable.

When a rebuild is mandatory

  • The embedding model changed, or the model recorded in the index differs from what is expected now.
  • The index dimensions, primary key scheme or text template were upgraded.
  • The index directory was copied by hand or points at another library.
  • Index files are damaged or the consistency check fails.

Steps

  1. Confirm the target model exists in Ollama: ollama list.
  2. Rebuild the asset text index: python tools\asset_index.py --rebuild --model <model name>. The default is embeddinggemma-2:740m.
  3. Rebuild the documentation index: python tools\build_semantic_index.py --model <model name>.
  4. Rebuild the image index: python tools\asset_vision_encode.py sync --library "<library root>" --rebuild --model gemma2.
  5. Check the status back in the plug-in; reopen the plug-in window if needed so settings and environment variables apply.

Verify the result

asset_semantic_status shows available as true, model matching the target and count matching the number of assets; the semantic part of maya_docs(action="status") should be available as well.

Tips and warnings

  • Changing the model re-encodes the whole library and takes noticeably long with many assets; do not change it without reason.
  • The environment variables and the models recorded in the indexes must agree: the asset index reads SQUIRREL_ASSET_EMBED_MODEL and the documentation index reads SQUIRREL_EMBED_MODEL, and they must match or only half the system works.
  • Rebuilding the image index is heavy work, so prefer doing it while Maya is idle or unused.
