The plug-in has no central log hub; most diagnostic output goes to the Maya Script Editor, and you then look in the matching directory by problem type.

Symptoms

  • You want to report a problem but do not know which file to attach.
  • The Script Editor only shows part of the output, and the record disappears after a restart.
  • Crashes, bridging and AI installation each leave a pile of logs and you cannot tell which is relevant.

Possible causes

CauseHow to tellAction
Only the UI message was readThe UI shows one line while the full error is in the Script EditorOpen the Script Editor and reproduce once
Logs are split by featureBridging, AI installation and headless jobs each have their own filesFind the matching file in the table below
Logs were rotated or cleanedThe directory only holds the last few runsCopy them immediately after reproducing
The crash left no time to write logsThe process exited outrightCheck the crash dump and the Windows event log

Common log locations

LocationContent
Maya Script EditorMain output and tracebacks for plug-in runtime, import/export, rendering and material conversion
~\.squirrel_asset_manager\bridge_port.logcommandPort port assignment, conflicts and fallback ports
~\.squirrel_asset_manager\bridge_recover.logDisconnect self-healing, cleanup, launch and re-dispatch records
~\.squirrel_asset_manager\broker_boot.logWhy registering with the AI broker failed at Maya startup
<package>\dsh_home\dsh_install.logdsh installation process
<package>\dsh_home\broker_daemon.logAI broker process output
<package>\dsh_home\squirrel_web_<instance>.logdsh front-end startup output
%TEMP%\squirrel_asset_manager\ai_install.logAI dependency installation log
%TEMP%\squirrel_standalone_host.logStandalone host startup log
worker.log in the headless job working directoryJob logs for headless thumbnail generation, format conversion and similar
%TEMP%\MayaCrashLog<date>.<time>.dmpMaya crash dump
Windows Event Viewer → ApplicationCrash module name, fault offset and exception code
%TEMP%\squirrel_pre_render\Scene backups taken before rendering, not logs

dsh_home is the dsh_home directory inside the plug-in package by default; if SQUIRREL_DSH_HOME or DSH_HOME is set, the environment variable wins.

Steps

  1. Open the Maya Script Editor, clear it, reproduce the problem and copy the full traceback.
  2. Locate logs by problem type: bridge_* for bridging, dsh_home for AI, ai_install.log for installation.
  3. For crashes, also record the module name and offset from the event log and keep the matching dump.
  4. Copy the key snippets into your report instead of just saying "it errored".
  5. For long logs keep the beginning, the end and the area around the timestamp, and state when you reproduced it.

Verify the result

You can state clearly which layer failed and point at the log or dump from the matching time.

If it still fails

  • Copy logs right after reproducing so the next launch does not overwrite them.
  • If a directory does not exist, that feature never reached the logging step; go back to the troubleshooting page for that feature.
  • If you are unsure which file to read, work through 6.8.2 "Diagnostic workflow" layer by layer.
  • When submitting feedback, use 6.8.3 "Feedback template" and include log paths and key snippets.
