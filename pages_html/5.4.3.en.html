Per-version materials give one version its own .zmetal and textures, so importing that version can restore just that look.

What it is

The asset root can hold a shared material node.zmetal; a version directory can also hold variants/<version>/node.zmetal with its own texture directory. The latter is that version's own material.

How it is chosen at import

  • When importing a version's material the plug-in reads variants/<version>/node.zmetal first.
  • When that version has no material of its own it falls back to node.zmetal in the root.
  • The textures of a per-version material are resolved within the version directory and written per the texture import policy.

Entry points

  1. A version root's .zmetal appears in the 「导入版本 / LOD」 (Import version / LOD) submenu and can be imported by clicking it.
  2. variants/<version>/node.zmetal is resolved and imported by import_variant_material; whether the matching interface menu entry is wired up is to be confirmed, so today it is used through that import function or an AI command.
  3. When that import fails it reports 「无法导入版本 … 的材质，请确认该版本包含独立的材质文件」 (cannot import the material of version …; confirm that version contains its own material file).

When it is needed

  • Different versions of the same model use different colors or textures.
  • A version must keep its own look without changing the shared material.

Tips

  • Per-version materials are written when a new version is exported, depending on whether zmetal export was checked for that export.
  • The .zmetal entries in the 「导入版本 / LOD」 (Import version / LOD) submenu go straight to a material import, while the version material menu resolves explicitly per version.
  • When a version material has the same name as the shared one, Maya renames it automatically in the scene and never overwrites the existing material.
