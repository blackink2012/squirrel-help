These problems usually come with an explicit error: model not found, index not built yet, index model differing from what is expected, or an index belonging to another library.

Symptoms, causes and fixes

Model not found: the needed model was never pulled, or settings keep a deleted model name. Check with ollama list, pull the model, or choose an available model in the configuration.

No asset library semantic index yet: that library never had one. Open the library and wait for the background warm-up, or run python tools\asset_index.py --sync.

Index model differs from the expected one: the embedding model changed, or the index came from another configuration. Rebuild as prompted: python tools\asset_index.py --rebuild --model <model name>.

Index belongs to another library: the index directory was copied by hand or points at the wrong place. Remove the override variable so the index returns to the in-library directory, or rebuild to take it over once the original library no longer needs it.

Image retrieval unavailable: the sidecar venv is missing, numpy / Pillow are absent, or the image index was never built. Rerun the image part of the one-click install and then python tools\asset_vision_encode.py sync --library "<library root>".

Documentation semantics unavailable: the documentation index is missing or the model differs. Run python tools\build_semantic_index.py --model <model name>; lexical retrieval still works without it.

Verify the result

asset_semantic_status reports available with a matching model, and the semantic part of maya_docs(action="status") is available too.

If it still fails

First check whether the index points at the wrong directory and then read the logs; never bypass the ownership check by copying an index directory by hand.
