One-line summary: copy files of the chosen formats from a source folder to a target folder in bulk — with a dry run first so you can see what would be copied.

It only copies files and never changes content, imports into the library or touches Maya. "Mirror" here means "copy the matching files over", not two-way sync, and it never deletes extra files in the target.

A complete flow

  1. Quick tools → Batch mirror copy;
  2. Choose the asset directory as Source folder and the destination as Target folder (a new directory is easiest);
  3. Fill the formats you want, such as .png, .jpg;
  4. Tick Preview only (do not actually copy) and click Start copy;
  5. Read the totals at the end of the log and sample a few [preview] would copy lines to confirm the scope;
  6. Untick Preview only and decide whether to tick Copy hierarchy;
  7. Click Start copy again; this time it really copies;
  8. Read the final "operation finished: total X, copied Y, skipped Z, failed W".

Where the output lands

  • Copied files land in the target folder;
  • With Copy hierarchy ticked the source subdirectory structure is rebuilt under the target; unticked, everything piles into the target root (which is how same-named files collide, see below);
  • Failed files appear in the log as [failed] path - reason and are counted in the final totals.

Behaviors to know

  • A same-named file already in the target is skipped, with [skipped] already exists: path in the log — it never overwrites. So "replace the old with the new" cannot be done here: delete or rename the old file in the target before copying.
  • It only copies: no deleting and no renaming: extra old files in the target are left alone and never cleaned.
  • Without Copy hierarchy, same-named files from different subdirectories collide in the target root and the later one is skipped as "already exists" — so whenever the source has duplicate names, tick Copy hierarchy.
  • Because the strategy is "skip if it exists", clicking Start copy repeatedly is safe and never piles up duplicates.

Risks and how to undo

  • Its only write is "add files to the target directory": no overwrite and no delete, so the risk is low.
  • The worst case is "the target gained a pile of files": delete them using the [copied] paths in the log, or simply delete the whole target directory and start over.
  • The one thing to be careful about is choosing the wrong target directory (pointing at a project directory in use, for example), where the copied files would mix into the project. Check the target path before running.
