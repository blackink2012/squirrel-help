Every command is called and returns through the same structure: the caller provides command_id, params and dry_run, and the broker replies with status, result and error.

Request parameters

FieldRequiredDescription
command_idYesCommand id; follow the params_schema in the command reference and manifest
paramsNoCommand parameter object; keys must come from that command's params_schema
dry_runNoPreview only, change nothing; default false
instance_idDepends on entryTarget instance; can be omitted when the chat runs inside Maya
session_idNoAudit owner, written to audit.jsonl
request_idNoHandle for progress and cancellation; the broker pre-generates it for async jobs
allow_cross_instanceNoBy default only the currently bound instance is touched

The unified executor signature is executor(dry_run=False, **params). Only commands declaring progress_supported / cancel_supported get the progress / cancel objects injected; commands that do not declare them raise TypeError if they receive them.

Command return

Commands return a dict with status set to ok, preview or error. preview is the dry_run preview, not a failure; the other fields are defined per command, for example changes, moved, created_ids, warning, missing.

The outer envelope is wrapped uniformly by /execute or squirrel_execute_command:

{"status": "ok", "result": {"status": "ok"}, "error": null}

An inner status="error" is promoted to an outer error, so only an outer ok means real success. A single response is capped at 262144 bytes; when exceeded it returns truncated: true, original_bytes and content_prefix, in which case use a more precise query (add limit, specify fields, or batch).

Tip: Never guess parameter names. The same field name can mean different things in different commands; the manifest's params_schema is the only authority.
