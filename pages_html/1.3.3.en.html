An asset library is an ordinary folder: assets are .zasset folders, metadata is JSON, and copying the library directory is a complete backup.

Library root

The root contains 11 built-in sub-library directories; any missing one is created when the library loads:

your asset library/
├── library.json            # library metadata
├── favorites.json          # favorites
├── materials/              # materials
├── models/                 # models
├── lights/                 # lights
├── textures/               # textures
├── scenes/                 # scenes
├── hdr/                    # HDR
├── ani/                    # dynamics
├── images/                 # images
├── audio/                  # audio
├── animation/              # animation data
├── nodetree/               # node trees
└── .squirrel_ai_index/     # semantic index (derived data, rebuildable; official/ and ollama/ per backend)

Two rules that are easy to mix up, so keep them apart:

  • The 「创建资产库」 (Create asset library) button in settings creates only 6 base directories: materials, models, lights, textures, scenes, hdr;
  • Every time a library is loaded or switched to, the plug-in completes the directories for all 11 built-in sub-libraries (creating whatever is missing, plus FolderMetadata.fdata); if the library root has no library.json yet (first run), or a sub-library has no sub-categories, it also creates sub-categories from the default configuration.

Each sub-library and category directory also holds a FolderMetadata.fdata recording its display name and type; top-level categories cannot hold assets directly, assets go into their sub-categories.

A single asset

MyAsset.zasset/
├── meta.json               # name, category, tags, formats and so on
├── node.zmetal             # material node (optional)
├── node.ma / .fbx / ...    # geometry (optional)
├── thumb.sicon             # static thumbnail (optional)
├── thumb.aicon / .mp4      # animated thumbnail (optional)
├── textures/               # textures (optional)
└── deps/                  # collected caches, proxies, references (optional; called associated/ in older versions)

Settings and logs

  • Application settings: ~/.squirrel_asset_manager/app_settings.json.
  • Bridge and recovery logs: bridge_port.log, bridge_recover.log, broker_boot.log and others in the same directory.
  • Semantic index: by default under the library root, .squirrel_ai_index/<official|ollama>/ (split by backend); a local index root can also be set in settings.

Data safety

  • Backup: close Maya and copy the whole library directory together with app_settings.json; assets are not a database, so a single .zasset can also be copied on its own.
  • Settings writes: settings are written atomically by replacing a temporary file; a corrupt settings file is first backed up as .bak and then reset to defaults.
  • Index: derived data that can be rebuilt; do not put it on a shared or synced drive, because multiple writers are not coordinated across machines and can overwrite each other.
  • Concurrency: the library itself has no cross-machine file lock; when several people share it, avoid renaming or moving the same asset at the same time (the exact lock strategy is to be confirmed).
