同版本多开或崩溃后快速重启时，Maya 会自动从默认端口退到备用段 7110~7129，客户端会连同备用段一起探测。

为什么会换端口

启动块先尝试本版本默认端口。若该端口已被同版本的另一台实例占用（Maya 报 10048），就依次尝试 7110~7129，并把结果写进 ~/.squirrel_asset_manager/bridge_port.log。

客户端候选端口顺序为：首选年份（2026）→ 更老的年份 → 更新的年份 → 备用段。也就是说，备用段里的实例同样能被自动发现。

操作步骤

  1. 执行 python maya_bridge.py --scan，查看每个候选端口是否在线。
  2. 按版本连接时用 python maya_bridge.py --maya 2025，它会在默认端口与备用段之间逐个探测，并用 ping 返回里的年份确认身份。
  3. 已知具体端口时用 python maya_bridge.py --port 7110 --ping。
  4. 客户端只认某个端口时，可设 SQUIRREL_MAYA_PORT=7110。
  5. 排查换端口历史时查看 ~/.squirrel_asset_manager/bridge_port.log。

结果验证

--ping 返回 版本 | 场景；--doctor 会逐端口列出监听、应答、PID 与判定结果。

提示与警告

  • netstat 显示 LISTENING 不等于 Maya 活着：卡死实例或崩溃报告器进程也会占着端口。判定必须真投一条命令看它答不答。
  • 探针要用正常表达式（如 ping），不要用 print；commandPort 回传的是表达式的值，print 只会让调用方收到 None，把健康实例误判为卡死。
