One-line summary: four kinds of housekeeping — fix the display, fill gaps, produce evidence and roll back — live behind this one button. It never touches asset content itself, only the manifest, thumbnails, invalid entries, logs and overwrite history.

How to open it

On the top toolbar, between Panels and layout and Maya target, is the wrench / maintenance icon (tooltip "Maintenance: rebuild index / export diagnostic log"). Click to open the menu; nothing needs selecting first.

Rebuild asset index: when to use it

  • Assets clearly exist on disk but are missing from the list, or the count does not match;
  • You reorganized the library directory by hand (not recommended), or suspect the manifest cache is corrupted;
  • First open after moving machines or copying the whole library.

It means "read the disk again" — not "recompute thumbnails" — and it changes no asset metadata.

Fill missing thumbnails: render the whole library

Instead of right-clicking Background render one asset at a time, this item scans the entire library:

  • Candidates are assets missing thumb.sicon or holding only a placeholder; the two kinds are tagged "Missing thumbnail" and "Placeholder only" in the list;
  • The list is selected entirely by default; adjust with Ctrl / Shift; right-click offers Locate asset / Open asset path / Remove from list (removal affects this list only and the item returns on a rescan);
  • Start generating first asks for renderer / preset model / environment light / size and quality (8.12.6), then a separate mayapy process renders in batch (progress window in 8.12.7);
  • Rendering overwrites those assets' existing thumbnails; the job runs in the background and does not occupy the current Maya viewport.

The older "fill geometry formats" entry has been removed: format conversion needs source geometry, so with zero geometry there is nothing to fill. Per-asset format conversion is still under right-click Format conversion (8.5.16).

Clean invalid assets: look first, then decide

It scans two kinds: "missing meta.json" and "empty shell (no meta, no valid files)":

  • Right-click offers Open asset path to check by hand, Remove from list (list only, nothing on disk), and Repair: restore meta.json;
  • Repair all at the bottom only processes entries with a valid format file; empty shells are skipped and counted;
  • Clean all (move to recycle bin) at the bottom is the only action that touches the disk; after confirming, the entries go to the recycle bin and can be restored from the left column (8.8.3);
  • After repairing or cleaning, the main window rescans and refreshes automatically.

Export diagnostic log: what the bundle holds

ContentDescription
LogsPlug-in runtime logs (error stacks, command timings and so on)
Desensitized configuration snapshotStructure and values of app_settings.json and similar, with sensitive fields desensitized
Asset manifestAsset / category index of the current library, used to reproduce "which record is wrong"

It does not include thumbnails, models, textures or any other asset file content, so it is safe to send to support.

Restore historical version

History comes from overwrite export: before each overwrite of the same asset, the old version is snapshotted (the last 5 versions or 30 days by default). Pick a timestamp in the window and click Restore selected version; the files return to their original place, and the restore itself creates a new history entry.

  • An asset that was never overwrite-exported → the window says "This asset has no overwrite history yet";
  • Opening the menu item without selecting an asset → you are asked to select one in the grid first;
  • When several files were overwritten in several passes, restoring processes them file by file, and partial failures report success / failure counts separately.
