库体检异常时，先看 library_health 的四个判据：是否已加载、资产与分类数量、重复 UUID、加载失败清单。

症状

  • 资产总数与磁盘上的 .zasset 数量不一致。
  • 资产明明在库目录里，插件网格中却找不到。
  • 收藏夹、版本或分类引用错乱，重扫后仍不恢复。
  • library_health 返回 is_loaded 为假、has_duplicate_uuids 为真，或 load_failure_count 大于 0。

可能原因

原因判断方法处理
库没有成功加载is_loaded 为假，资产数为 0检查库路径与权限，再重扫
索引缓存过期分类树或资产数与磁盘不一致清缓存后重新加载
重复 UUIDhas_duplicate_uuids 为真预览后修复重复 ID，并重扫
资产元数据损坏load_failures 中某条带 reason从备份恢复，或重新导入该资产
配置与磁盘不一致子库或分类数量对不上重新读取配置
多人/多机同时改库索引落后或互相覆盖让索引放本地目录，必要时重建

解决步骤

  1. 执行 library_health，op=status，记录库根、是否加载、资产数、分类数、重复 ID 与加载失败数。
  2. 查看 load_failures 中每条资产的 reason，确认是缺文件、元数据损坏还是版本不兼容。
  3. 缓存问题先执行 op=clear_cache，再执行 op=reload，让插件按磁盘重建索引。
  4. 配置问题执行 op=reload_config，重新读取子库与分类配置。
  5. 有重复 UUID 时，先用 op=fix_uuids 配合 dry_run=True 预览，再正式执行；修复后会自动重扫。
  6. 单个资产元数据损坏时，先备份该 .zasset，再从备份恢复或删除后重新导入。

结果验证

再次执行 op=status 时，is_loaded 为真，has_duplicate_uuids 为假，load_failure_count 为 0，资产数与磁盘一致。

仍不行怎么办

  • 修复重复 UUID 后，收藏夹等保存了旧 ID 的地方可能需要重新核对。
  • 先备份整个资产库，再逐个排查加载失败的资产；不要直接批量删除库目录。
  • 多机共用库时，把语义索引放到本机本地目录，避免索引文件互相覆盖。
  • 反馈时附 library_health 的 status 返回、加载失败清单和最近一次重扫日志。
