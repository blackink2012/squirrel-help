崩溃后按「体检 → 清卡死或点掉模态框 → 拉起并自证」三步走，不要反复重开或直接杀进程。

症状

  • Maya 突然消失、白屏或长时间未响应。
  • 工具报告断连，重开 Maya 后仍然连不上。
  • 新 Maya 启动后客户端报「端口被占用」或「连接被拒」。
  • 崩溃前的未保存场景找不到了。

可能原因

原因判断方法处理
Maya 进程已经崩溃进程消失，%TEMP% 有新的崩溃转储按三步恢复
主线程卡死进程在、端口监听但不应答确认后清理卡死实例
模态对话框挡住Maya 窗口有恢复/报错/未保存提示先点掉对话框
旧实例占着默认端口新实例退到 7110–7129扫描备用段并连实际端口
渲染器或插件带崩 Maya事件日志指向渲染器 DLL见 6.7.3「渲染器崩溃」
未保存场景丢失自动保存目录为空或未开启见 6.7.4「自动保存与恢复」

解决步骤

  1. 体检：运行 python maya_bridge.py --doctor。它只报告谁在线、谁卡死、谁该清。
  2. 先看 Maya 窗口，如果有模态对话框就点掉，再跑一次 --doctor；确认是卡死而不是对话框后，运行 python maya_bridge.py --doctor --kill-hung。
  3. 拉起：运行 python maya_bridge.py --doctor --launch，它会等待 Maya 真正能应答，而不是只看进程是否启动。
  4. 收尾确认：运行 python maya_bridge.py --ping 或 --scan，确认版本、场景与实际端口。
  5. 需要重投任务时，只对幂等或只读任务使用 --retry-if-crashed；任务文件里写了 SQ_DESTRUCTIVE = True 时程序会拒绝自动重投。
  6. 恢复未保存内容时，查看自动保存目录与 %TEMP%\squirrel_pre_render\，先复制出来再打开。

结果验证

--doctor 报出可用的 healthy_port，--ping 返回 Maya 版本与当前场景，新任务能正常执行。

仍不行怎么办

  • 不要连续重开多个 Maya，先确认旧实例是否还占着端口。
  • 查看 ~\.squirrel_asset_manager\bridge_port.log 与 bridge_recover.log，确认端口变化和自愈记录。
  • 崩溃取证看 Windows 事件日志（模块名 + 偏移）和 %TEMP%\MayaCrashLog*.dmp。
  • 破坏性任务绝不因为一次断连就重跑；先查迟到结果和作业历史。
