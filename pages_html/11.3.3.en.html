The texture import policy decides where textures are read from and whether they are copied into the project when importing materials or textures from the library.

Effect

It controls where textures under textures/ inside a .zasset end up in Maya.

Values and defaults

OptionBehavior
Copy textures into the projectExtracts textures to {project}/sourceimages/squirrel_asset/{asset name}_{last 4 of ID}/ and points the material there
Current asset directory (default)No copying; the material points directly at textures/ inside the .zasset
Source file directoryPrefers the original absolute paths recorded at export, falling back to in-asset paths when they do not exist
  • The preset file currently holds asset_directory; when that key is missing the code falls back to copy_to_project.

Scope

  • Material import, light texture import, texture assignment and reference import — every path that reads textures from an asset.
  • It only changes the paths after import and never modifies the asset package.
  • It is stored as texture_import_policy in config.json.

When to change it

  • The asset must be delivered to another machine, or the project must be self-contained: choose 「拷贝贴图到项目」 (Copy textures into the project).
  • Single-machine use where disk space matters and assets should stay together: keep 「当前资产目录」 (Current asset directory).
  • Textures still live in the original working folder and should stay editable: choose 「源文件目录」 (Source file directory).

Tips

Warning: 「源文件目录」 (Source file directory) relies on the absolute paths recorded at export; after moving machines or directories the textures are not found, so switch to one of the first two options.

Tip: copying into the project creates a sub-directory from the asset name and the last four characters of the ID, so different assets never overwrite each other.
