In one line: a safety catch that is off by default — once enabled, 「彻底删除」 (Delete permanently) in the context menu works, and deleted files vanish immediately without entering the recycle bin and cannot be restored.

Where it is

Settings window → General page → the 「彻底删除」 (Permanent delete) group (between "Appearance" and "Thumbnails (resolution)").

While it is off (default)

  • 「彻底删除」 (Delete permanently) in the asset / category / version context menus is greyed out, and clicking it suggests enabling it in settings;
  • Deletion only offers "move to recycle bin": files stay in the library and can be restored;
  • The recycle bin is limited to 100 GB, and when full you must permanently delete items inside it (see 15.8.3).

Steps to enable it

  1. Check 「启用「彻底删除」（直接删除文件，不进回收站）」 (enable permanent delete, removing files directly without the recycle bin);
  2. Clicking 「应用」 (Apply) or 「确定」 (OK) opens a second confirmation stating that files are removed directly, do not enter the recycle bin and cannot be restored;
  3. It takes effect immediately after confirming; back in the asset grid, 「彻底删除」 (Delete permanently) is no longer greyed out.

Enabling and disabling both write an audit log (setting / permanent_delete_enabled, marked irreversible) so the change can be traced later.

Once it is on

ActionBehavior
Delete → move to recycle binAs before: goes to the recycle bin and can be restored
Delete → delete permanentlyDeletes the files on disk, skips the recycle bin; the confirmation says "cannot be restored"; there is no undo
AI-side asset deletionControlled separately by 「允许 AI 删除 / 覆盖替换资产」 (allow AI to delete or overwrite assets) in AI settings and unrelated to this switch (see 11.4.6)
警告

Permanent delete keeps no backup, skips the recycle bin and cannot be undone. Keep this switch off for day-to-day work; enable it temporarily only when space must really be freed and the library is backed up. See 4.12.4 for backups.
