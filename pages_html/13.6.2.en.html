When Maya shows "not responding" with CPU near 0%, it is usually waiting for a main-thread task to return rather than lacking compute; first decide whether it is frozen or waiting.

Symptoms

  • The UI shows "not responding" while Maya's CPU usage in Task Manager is near 0%.
  • Opening the AI panel or switching libraries takes tens of seconds.
  • Consecutive thumbnail renders get slower and slower, eventually crashing.
  • Memory keeps climbing and does not drop noticeably after closing the plug-in window.

Possible causes

CauseHow to tellAction
A long task runs synchronously on the main threadCPU low, UI frozen, recovers when the task finishesWait for it, or switch to an async/batch interface
A nested event loop on the main threadThe UI never returns while CPU stays near 0%Stop such scripts and restart Maya
Consecutive renders in the same processThe second render starts hanging or crashesSee 6.7.3 "Renderer crash"
Many thumbnails decoded at onceStuttering while scrolling, disk and memory risingWait for async loading and reduce the first-screen count
The semantic embedding model stays residentOllama uses hundreds of MB in Task Manager (about 639 MB measured for the 0.6B tier; varies by model)Stop Ollama when semantic search is not needed
Index/cache files are largeCache files in the library directory reach several MBSplit the library, or rebuild the index
Several Maya instances at onceMultiple processes load libraries and thumbnails simultaneouslyReduce parallel instances

Steps

  1. Check Task Manager first: CPU near 0% and frozen for a long time means the main thread is waiting; do not keep clicking.
  2. Confirm whether a render, batch import/export or AI panel is in progress; do not trigger it again before it finishes.
  3. Use async interfaces for batch tasks, provide progress and cancellation checkpoints in long loops, and never spin on the main thread.
  4. Scripts and tools must not poll with sleep on the Maya main thread, nor nest processEvents() loops.
  5. Load thumbnails and previews in batches; close preview panels you do not need and extra split-instance panels first.
  6. If it hangs or crashes after consecutive renders, fully restart Maya instead of hot-reloading the plug-in.

Verify the result

The UI responds again, tasks complete normally, memory drops after a task ends, and the permanent "not responding" state is gone.

If it still fails

  • Record what was running before the hang, how long it lasted, and the CPU/memory usage at the time.
  • Repeat the same operation in an empty scene to rule out scene size or third-party plug-ins.
  • If the bridge or AI panel hangs, use 6.7.1 "Port listens but does not answer" to check whether Maya is really alive.
  • For recovery after a crash, follow 6.7.2 "Three steps to recover after a crash" and keep the crash dump.
