When some attributes fall back to defaults or clearly wrong values after conversion, it is usually a missing mapping row, a target attribute that does not exist, or differing units / semantics on the two sides.

Symptoms

The new material's color, roughness or metalness differs from the source; a light's color is right but its intensity is far off; the Script Editor prints 「目标属性不存在」 (target attribute does not exist), 「使用默认值」 (using the default value) or 「属性写入未生效」 (attribute write had no effect).

Common causes

  1. The .mmap has no row for that source attribute, or the row has no target_attribute.
  2. The source attribute does not exist on the current source node, so the tool falls back to default_value.
  3. The target node does not have that attribute (different renderer version or plug-in).
  4. The semantics differ: glossiness versus roughness, transparency versus transmission and light intensity units are not equivalent.
  5. The attribute is read-only: setAttr reports no error but the value never changes.

Steps

  1. In the Maya Script Editor read the exact attribute names and messages to tell "missing mapping" from "target attribute missing".
  2. Add rows with the material node attribute mapping tool: source attribute on the left, target attribute on the right; pick a transform function and fill parameters when a conversion is needed.
  3. Save the .mmap into Assets/material_mapper_presets and run the conversion again.
  4. For lights across renderers note that only intensity is copied directly by default; when conversion is needed use light_intensity_scale in the mapping with a scale factor.
  5. Read-only attributes can only be replaced by attributes the target supports, or by writable attributes on the renderer side.

Verify the result

After converting again the succeeded attribute count grows and default-value rows shrink; the target values match the source material or the conversion rules.

If it still fails

  • Use 「属性映射预览」 (Attribute mapping preview) in the material conversion tool to check every row.
  • Same-named attributes do not imply the same semantics; never rely on name-only copying.
  • When the target attribute really does not exist, change the target material type or add a mapping to a similar attribute.
