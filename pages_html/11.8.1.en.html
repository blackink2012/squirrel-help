Supported formats define which file extensions the library treats as importable asset files: one per line, each with a leading dot.

What it does

The list is written to asset_file_extensions in Assets/preset/config.json. The library reads that field and uses it in two places:

  1. The file filter of the Import from file dialog, which then lists only these extensions.
  2. When a whole folder is collected into the library, it decides whether a root-level file counts as an asset file and takes part in grouping.

Values and defaults

One extension per line, for example .ma or .png. The factory list contains:

.zasset, _zasset, .ma, .mb, .fbx, .obj, .abc, .usd, .usda, .usdc, .glb, .gltf, .dae, .ass, .rs, .proxy, .vrmesh, .vdb, .png, .jpg, .jpeg, .exr, .hdr, .tga, .tiff, .tif, .bmp, .psd, .sicon, .aicon, .mcm, .wav, .mp3, .aiff, .aif, .flac, .ogg, .m4a, .aac, .atom (40 entries).

Scope of effect

  • It affects which file types Import from file can see, and how root-level files are recognized when a folder is collected.
  • It does not affect the geometry and image extensions in Other configuration; those only classify files when a whole folder is collected.
  • When a single file is collected, the sub-library type is still inferred from the built-in extension table; changing this list does not change that result.

Steps

  1. Open Settings → Supported formats.
  2. Tick Unlock all settings.
  3. Add or remove extensions line by line; one per line, and do not drop the leading dot.
  4. Click Apply or OK.

Verify the result

Reopen Import from file: the file filter should include the new extension. Existing assets are not affected.

Tips

A wrong configuration breaks asset import. Back up config.json first if you are unsure.
