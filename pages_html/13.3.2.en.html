A blank thumbnail usually means the .sicon is missing or invalid, the render did not actually produce an image, or the grid still caches old pixels.

Symptoms

  • The asset card shows a gray square, but opening the asset shows its name and category.
  • Only some assets are blank, typically the first one created in a batch, or one whose thumbnail was just updated.
  • Refreshing changes nothing; the new image appears only after closing and reopening the plug-in window.
  • The Script Editor shows [Render] 未找到输出文件 (output file not found) or [Batch] ... 保留占位图 (keeping placeholder).

Possible causes

CauseHow to tellAction
Neither render attempt produced an imageThe log says the thumbnail failed to render twiceUse playblast, import an image, or headless generation instead
thumb.sicon does not existThe asset directory has no thumb.siconCapture, import or render it again

Animated image fails to loadAn .mp4 thumbnail shows a play-icon placeholderReplace it with a still image, or check the video file

Steps

  1. Right-click the asset, open Update thumbnail and try Capture or Import first to confirm the write path works.
  2. When a render is needed, prefer Update thumbnail → Background render (headless offscreen), or try Maya playblast first.
  3. Check whether thumb.sicon exists in the asset directory and opens in an image viewer.
  4. Refresh the current category, or switch to another category and back, so the grid re-reads the thumbnail.
  5. If the old image still shows, close and reopen the plug-in window to clear the grid's pixel cache.
  6. In batch creation, if only the first asset is gray, generate it again; the program retries a failed thumbnail once by itself.

Verify the result

The asset card shows a real thumbnail, it persists after reopening the plug-in window, and the log no longer reports "keeping placeholder".

If it still fails

  • Test with another asset to tell whether it is one asset or a whole batch.
  • Check the [Render], [Batch] and [Export] logs in the Script Editor to see whether nothing was rendered or the write failed.
  • Handle renderer-related failures per 6.7.3 "Renderer crash"; check library anomalies per 6.3.3 "Library health anomalies".
  • When reporting, include the thumbnail file name and size in the asset directory plus the relevant log lines.
