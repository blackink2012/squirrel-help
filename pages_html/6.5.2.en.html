If textures turn pink or black after import, or the asset has no textures/ or deps/, first confirm whether the files were actually packaged at export time.

Symptoms

  • After importing, the material shows pink or black and texture nodes point at empty paths.
  • The .zasset has no textures/, or deps/ lacks the matching cache, proxy or reference files.
  • dependencies_missing in meta.json is not empty and the export log reports missing dependencies.

Common causes

CauseHow to tellFix
Texture paths were already broken at exportThe file node's path does not exist in MayaRelocate the textures with the File Path Editor, then export

"Collect linked files" was not checkedCaches / proxies / references are not in deps/Check it and export again
Dependencies are outside the collection scopedependencies_out_of_scope has entriesPut the dependencies on an accessible local path or deliver them alongside the asset
Paths contain unparsable tokensdependencies_unresolved_tokens has entriesExpand the paths into real file paths and export again
Referenced files are not loadedThe reference node state is unloadedLoad the reference in Maya first, then export or collect

Steps

  1. In Maya check the selected objects' file, aiImage and similar texture nodes and confirm the paths point at real files.
  2. When exporting again keep 贴图 textures/ (textures), and check 收集场景中已挂载的缓存/代理/引用文件 (collect caches / proxies / references) when caches, proxies or references exist.
  3. After export check whether the matching files appear in .zasset/textures/ and .zasset/deps/.
  4. Open meta.json and read texture_map, dependencies_missing, dependencies_out_of_scope and dependencies_unresolved_tokens.
  5. On import use the asset's own import entry, which remaps the original paths to in-package paths through texture_map.

If it still fails

  • Search the Script Editor for [StageTextures], [Export] 依赖 and [Export] 依赖警告 to see whether collection failed or the path itself is broken.
  • Verify on another machine: if the other machine sees the textures, the problem was the path on the original machine rather than the asset structure.
  • A .ma file keeps the original absolute texture paths from export time, so you cannot judge missing textures from the .ma text alone; trust textures/ and texture_map.
