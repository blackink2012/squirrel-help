A modal dialog holds the Maya main thread and makes every remote command wait as well; it looks much like a hang, but dismissing the dialog restores everything.

Symptoms

  • Commands time out for no clear reason while the Maya process is alive and the port still connects.
  • --ping takes very long, or the next command times out right after a reply.
  • The Maya window shows a pending dialog: save prompt, license notice, Arnold error, crash-recovery box and so on.

Cause

A modal dialog enters its own event loop and occupies the main thread, so remote code only runs once it closes; this is not a bridge or port failure.

Fixes

  1. Call maya_modal_probe (read-only), which returns active_modal, modals and a summary you can relay directly.
  2. Switch to the Maya window based on the reply and decide by hand, then dismiss the dialog.
  3. After dismissing it, run a read-only query again to confirm the main thread recovered.
  4. When the dialog asks whether to save, decide to save or discard before continuing.

Verify the result

maya_modal_probe no longer reports an active modal, --ping replies normally and later commands return within the expected time.

Tips and warnings

  • The probe is read-only: it never clicks or closes anything, because whether to save is the user's decision.
  • Never force-close dialogs with a script; read the content first so no data is lost.
  • If it still times out after dismissing the dialog, continue with "Main thread hangs".
