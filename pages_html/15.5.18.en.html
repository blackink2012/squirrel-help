One-line summary: versions / variants / LODs are not independent assets but entries inside a master asset; right-clicking them gives two reduced menus that only act on "this one copy".

How to get here

  1. Right-click the master asset card → expand the Import ▶ submenu;
  2. Click View versions / View variants / View LOD management;
  3. The asset area switches to the internal view where cards become version / variant / LOD entries;
  4. Right-click an internal entry card.

SegmentItemDescription
①Import <format>Imports only this copy (this version / variant); with a single format the row shows the format name
①Add referenceBrings this copy in as a Reference
①View LOD managementAppears when the entry has several LODs; switches to its LOD list
①Append LOD…Appends a new LOD to this copy
②Add to favorite set ▶It favorites the master asset (internal entries cannot be favorited themselves)
②Select all / duplicate / open folderDuplicate and open folder both act on the master asset; internal entries are never duplicated
③EditUnavailable on the main version (gray, tagged "(main version)")
③Update thumbnail ▶Capture / import; variants also have Maya playblast / render image; add / capture and add. No background render
③Update asset ▶Version entries offer: replace asset / append format / append as LOD / create new version (gray on sub-versions) / add new variant… / batch add variants…; variant entries have only one Update asset row
③DeleteThe main version cannot be deleted (gray, stating the main version cannot be deleted)
④Asset detailsOpens the version browser / asset inspection window

Why these menus are so short

Internal entries (versions / variants / LODs) are not real assets, only a slice of the master asset. Therefore:

What a normal asset can doWhy an internal entry cannot
Move to / copy to a categoryIt has no directory of its own and cannot be moved; move the master asset instead
Edit name / category / tagsMetadata lives on the master asset
Delete the whole assetOnly "this copy" can be deleted (LODs have a minimum), and deleting the package is done on the master asset
Render thumbnails in the backgroundBackground rendering works per whole package, and a single entry has none

There is a real upside: a mistake in this menu at worst changes this one copy and never the master asset's content or location.

Notes

  • Favoriting hits the master asset: favoriting from an internal entry puts the master asset in the favorite set, not this version.
  • "Set as default LOD" changes master asset behavior: the default LOD is the one used on import / drag, so think before switching.
  • Deleting a variant deletes only its own geometry and thumbnail: shared textures / materials are unaffected (the confirmation states this).
  • Paste does not copy internal entries: duplicating an entry never reaches the clipboard.
