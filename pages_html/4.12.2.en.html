An asset library has two rebuildable indexes: the directory index cache used at startup and the vector index used for semantic search; the first invalidates itself, the second must be rebuilt manually.

The two indexes

IndexDefault locationPurposeHow to rebuild
Directory index cache<library root>/.squirrel_index_cache.jsonSpeeds up opening the librarylibrary_health op=clear_cache then op=reload, or delete the file and refresh
Semantic index<library root>/.squirrel_ai_index/<official or ollama>/AI semantic search and search by imagepython tools/asset_index.py --rebuild --library "<library root>"

Steps: directory index

  1. Run library_health op=clear_cache to delete the cache file.
  2. Run library_health op=reload, or click the toolbar refresh button, and wait for the scan to finish.

Steps: semantic index

  1. Confirm Ollama and the embedding model are available.
  2. In the plug-in package root run python tools/asset_index.py --rebuild --library "<library root>".
  3. Use --status to see the entry count and model, and --verify for a consistency self-check.

Verify the result

  • After rebuilding the directory index the asset count matches the number of .zasset folders on disk.
  • After rebuilding the semantic index --status shows entries and AI semantic search returns results again.

Tips

  • The directory cache invalidates itself by .zasset modification time and falls back to a full scan when incompatible.
  • The semantic index is derived data and by default follows the library directory; use the ai_asset_index_dir setting or the SQUIRREL_ASSET_INDEX_DIR environment variable to move it locally, which takes effect after reopening the window.
  • The index is split by backend (official and ollama each get one): vectors from the two backends are not interchangeable, and sharing a directory makes users of different backends mark each other stale and rebuild repeatedly.
  • When several people share one library, do not put the semantic index on a shared drive, or concurrent writes from the same backend will wait on each other.
  • Use --sync for incremental syncing; after changing the model or the text template you must use --rebuild.
