Work through "symptom → Script Editor → feature status → bridge health → crash forensics" in that order: first decide which layer the problem is in, then dig deeper.

Symptoms

  • The symptom is vague and you cannot tell whether it is the UI, asset library, AI, bridging or the renderer.
  • The same symptom can have several causes, and trial and error is expensive.
  • You need to give the maintainer information but do not know what to collect first.

Possible causes

CauseHow to tellAction
The full error was never readOnly the UI message was seenReproduce and capture the traceback first
The order jumps aroundReinstalling now, rebuilding the index nextWork layer by layer, one decision per layer
Status endpoints were not usedNo idea of the current library/index/AI stateCheck feature status first
Bridge and Maya state are confusedCannot tell a hung Maya from a client problemUse --doctor and --ping to prove liveness
Crash evidence was not preservedLogs and dumps were overwrittenCopy them right after reproducing

Steps

  1. Record the symptom: when it happened, what you were doing, whether it reproduces reliably, and the scope.
  2. Open the Script Editor, clear it, reproduce once and copy the start and end of the full traceback.
  3. Check feature status by problem type: library_health with op=status for the asset library; asset_semantic_status for search and AI; the dependency check in settings for AI dependencies.
  4. For Maya connection, hang or disconnect problems, run python maya_bridge.py --doctor, then use --ping and --scan to confirm instances and ports.
  5. For crashes, record the module name and offset from the Windows event log and keep %TEMP%\MayaCrashLog*.dmp.
  6. For rendering problems, confirm whether the crash is inside a renderer DLL; use 6.7.3 "Renderer crash" to decide whether out-of-process rendering is needed.
  7. If you still cannot locate it, organize the information per 6.8.3 "Feedback template" and submit it.

Verify the result

You can state clearly which layer failed (UI, asset library, index, bridge, renderer or licensing) and have the matching log or status return in hand.

If it still fails

  • Build a minimal reproduction: empty scene, single asset, single operation, to rule out scene and batch factors.
  • Keep copies of logs from before and after the reproduction, not just the last launch.
  • If you are unsure where logs live, look them up item by item per 6.8.1 "Log locations".
  • Include the steps you already tried so the maintainer does not repeat them.
