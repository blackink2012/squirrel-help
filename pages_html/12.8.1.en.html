When something breaks, check three places first: the live traceback in the Maya Script Editor, the bridge logs under ~/.squirrel_asset_manager/, and the broker and audit records under dsh_home.

User directory

~/.squirrel_asset_manager/ (on Windows, C:\Users\<user>\.squirrel_asset_manager\):

FileContent
app_settings.jsonPersonal settings; on corruption it is renamed to .bak or .corrupt_<timestamp>
bridge_port.logcommandPort results; also records the fallback to 7110–7129 when the default port is taken
bridge_recover.logSelf-heal records from --retry-if-crashed: disconnect reason, cleanup, launch and re-dispatch port
broker_boot.logWhy auto-registration with the broker succeeded or failed at Maya startup
broker_endpoint.jsonThe broker's actual TCP/HTTP ports; clients reconnect based on it
help_cache/Directory tree and page cache for the maya_docs online fallback

dsh runtime directory

Default <plugin package>/dsh_home/, overridable with SQUIRREL_DSH_HOME or DSH_HOME:

File/directoryContent
broker_daemon.logOutput of the standalone broker process; the reason it will not start is almost always here
ai_jobs.jsonlAsync job history, including status, results and final progress
audit.jsonlOne line per command call: command, parameters, risk level, session, instance and result summary
dsh_install.logdsh runtime installation log
squirrel_web_<instance>.logdsh web front-end startup output
sessions/, storages/Sessions and storage; broken sessions are moved to quarantine/ (renamed, not deleted)
skills/Skill bundles after landing

PathContent

In-app logs

  • The Maya Script Editor shows plug-in tracebacks and print output.
  • Quick tools such as batch processing and batch mirror copy show progress in their own log panel, some with save-as-text.

Tip: For crash forensics, check the Windows event log's "faulting module name + fault offset", the .dmp above and the bridge logs together; if the crash is inside the renderer's own dll, prefer out-of-process rendering.
