These three advanced fallbacks on the Other configuration page control how files are classified when a whole folder is collected, and which nodes count as material nodes during export.

What it does

Settings → Other configuration has three entries on the left, each taking one value per line on the right:

SettingJSON keyEffect
Geometry extensionsgeometry_extensionsWhen a whole folder is collected, root-level files matching these are treated as geometry and split into node.{ext}
Image / texture extensionsimage_extensionsFiles matching these under the same path go into textures/
Material node typesmaterial_node_typesUsed by asset export, right-click Update asset and batch export to decide which scene nodes are material nodes

Values and defaults

  • Geometry: .ma .mb .fbx .obj .abc .usd .usda .usdc .glb .gltf .dae .ass .proxy .vrmesh .vdb
  • Images: .png .jpg .jpeg .exr .hdr .tga .tiff .tif .bmp .psd
  • Material nodes: aiStandardSurface, standardSurface, lambert, blinn, phong, openPBRSurface, pxrSurface, aiHair, aiSkin, aiVolume, VRayMtl, RedshiftMaterial

Scope of effect

  • The first two only apply to collecting a whole folder into the library. Single-file collection and texture scanning use the built-in extension table; changing these does not affect them.
  • Material node types are the single source of truth for the three export paths. A missing node type means that material is not recognized during export.

Steps

  1. Open Settings → Other configuration and tick unlock.
  2. Pick a category on the left, then edit line by line on the right.
  3. Click Apply or OK to write back to config.json.

Verify the result

Check geometry and image classification with a whole-folder collection; check material detection by exporting a scene that contains the target material.

Tips

These three settings take part directly in library reads and writes; a wrong value breaks import and export. Back up config.json before changing them.
