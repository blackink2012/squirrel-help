For startup errors, read the full traceback in the Maya Script Editor first; it usually points directly at a missing module, a stale copy, permissions or licensing.

Symptoms

  • Clicking the plug-in entry opens no window, or the window flashes and closes.
  • The Script Editor shows a red traceback containing ImportError, AttributeError, PermissionError and so on.
  • The window opens, but the status line, category tree or AI panel fails to initialize.
  • Startup reports sq_license 不可用，进入只读模式 (license unavailable, entering read-only mode); features are limited but the program does not crash.

Possible causes

CauseHow to tellAction
Package or submodule not foundThe top of the traceback is No module named ...Follow 6.1.1 "Plug-in not loaded" to check the install path and userSetup.py
A stale copy or half-finished directory is loadedsq.__file__ is not in the install directory, or the directory only has Assets\Delete the stale copy and reinstall
Core module ABI mismatchExtension module load failure is reportedFollow 6.1.2 "Version and ABI mismatch"
Licensing module missingThe log shows sq_license 不可用The program enters read-only; confirm the package is complete, or activate on the license page
Install directory is not writableThe traceback points at creating directories or writing configuration or logsRestore directory permissions, or move to a user-writable location
Old configuration or cache conflicts with the new versionErrors cluster around settings, index or category loadingBack up the configuration, reset the matching cache, then restart Maya

Steps

  1. Open the Maya Script Editor, clear the output and click the plug-in entry again to reproduce once.
  2. Copy the first error line and the last few stack frames of the traceback; do not just capture the words "error".
  3. Run import squirrel_asset_manager as sq; print(sq.__file__) to confirm which copy is actually loaded.
  4. For a missing module or stale copy, reinstall as described in 6.1.1 "Plug-in not loaded"; for an ABI error, switch packages per 6.1.2 "Version and ABI mismatch".
  5. If errors appear only when AI, bridging or the status line initializes, check ~\.squirrel_asset_manager\broker_boot.log and bridge_port.log.
  6. After the fix, fully restart Maya and verify once more.

Manual launch (when the startup script does not take effect)

If neither the shelf nor the status line works but the install directory is complete, you can run the startup code manually in the Maya Script Editor (Python).

First confirm your install directory (it is the level that contains the squirrel_asset_manager folder):

Install methodDefault location
EXE install (with Maya integration)The directory chosen in the wizard, default %LOCALAPPDATA%\SquirrelAM; both SquirrelAssetManager.exe and squirrel_asset_manager\ are at this level

How to tell: the directory contains a squirrel_asset_manager folder with __init__.py and ui\main_window.py. If the plug-in started before, you can also run import squirrel_asset_manager as sq; print(sq.__file__) and strip the trailing \squirrel_asset_manager\__init__.py; what remains is the install root.

Put that path into INSTALL_DIR below (keep the r"..." raw string form; backslashes need no escaping). Leave it empty to auto-detect the default locations from the table above:

import os
import sys
import maya.cmds as cmds

# 1) Custom install directory: change only this line. Give the directory that CONTAINS
#    the squirrel_asset_manager folder, e.g. r"D:\Tools\SquirrelAM"; empty = auto-detect defaults.
INSTALL_DIR = r""

# 2) Build the candidate list: use the given path if set, otherwise auto-detect
app_dir = os.path.normpath(cmds.internalVar(userAppDir=True))
local_appdata = os.environ.get("LOCALAPPDATA") or ""
if INSTALL_DIR.strip():
    candidates = [os.path.normpath(INSTALL_DIR.strip())]
else:
    candidates = [
        app_dir,                                      # legacy script install: %MAYA_APP_DIR%
        os.path.join(app_dir, "scripts"),             # even older script install
    ]
    if local_appdata:
        candidates += [
            os.path.join(local_appdata, "SquirrelAM"),            # standalone default
            os.path.join(local_appdata, "SquirrelAssetManager"),  # previous standalone default
        ]
# Also accept a path pointing straight at ...\squirrel_asset_manager
candidates += [os.path.dirname(p) for p in list(candidates)]

install_root = next(
    (p for p in candidates
     if os.path.isfile(os.path.join(p, "squirrel_asset_manager", "ui", "main_window.py"))),
    "")
if not install_root:
    raise RuntimeError("squirrel_asset_manager not found; put the directory containing it into INSTALL_DIR")
if install_root not in sys.path:
    sys.path.insert(0, install_root)

# 3) Drop an empty namespace package cached earlier
pkg = sys.modules.get("squirrel_asset_manager")
if pkg is not None and not getattr(pkg, "__file__", None):
    for name in [n for n in list(sys.modules)
                 if n == "squirrel_asset_manager"
                 or n.startswith("squirrel_asset_manager.")]:
        del sys.modules[name]

# 4) Open the main window (running again only recalls the existing window)
from squirrel_asset_manager.ui.main_window import MaterialLibraryWindow
MaterialLibraryWindow.show_window()
print("Launched from %s" % install_root)

How to read the result:

  • The window opens normally: the plug-in itself is fine, only the userSetup.py startup block did not take effect. Append the code above to the end of Documents\maya\<version>[\<language>]\scripts\userSetup.py for the current version, or rerun the installer to write the startup block (see 6.1.1 "Plug-in not loaded").
  • Still No module named 'squirrel_asset_manager': INSTALL_DIR is empty or points at the wrong level; check it against the rule above and confirm the directory holds a complete package (not just Assets\).
  • Extension module or DLL error: ABI mismatch; switch packages per 6.1.2 "Version and ABI mismatch".

A manual run only affects the current Maya session. To be ready at every startup you still need the startup block in userSetup.py. When writing it there, keep INSTALL_DIR filled in — auto-detection only covers the default locations, so a custom directory will not be found without it.

Verify the result

The plug-in window appears, the Script Editor no longer shows the same traceback, and the category tree and status bar finish initializing.

If it still fails

  • Start with an empty scene to rule out interference from the scene itself or third-party plug-ins.
  • Temporarily disable other startup scripts to confirm several tools are not rewriting userSetup.py at once.
  • Collect information per 6.8.2 "Diagnostic workflow"; when reporting, include the full traceback, Maya version and install directory tree.
  • Never submit full license files or keys for licensing errors; provide only the status and error code.
