A health check reports the library root, asset and category counts, duplicate UUIDs and the load-failure list in one pass; it is the first step when an asset is on disk but missing from the list.

Prerequisites

  • The asset library is loaded (a live library manager exists).

Steps

  1. Open the plug-in window and confirm the target library is loaded.
  2. Call the library_health command with the default op=status.
  3. Use the table below to classify the problem.
  4. With duplicate UUIDs, run op=fix_uuids, which rewrites the duplicated IDs and rescans automatically.
  5. With load failures, read each reason, fix the asset's meta.json or run op=reload to rescan the disk.
  6. If the sub-library / category configuration looks wrong, run op=reload_config to reread config.json.

Status fields

FieldMeaning
library_rootCurrent library root
is_loadedWhether the library is loaded
asset_countNumber of indexed assets
category_countNumber of categories
has_duplicate_uuidsWhether duplicate UUIDs exist
load_failure_count / load_failuresAssets present on disk but not indexed, with reasons (at most 20 entries)

Verify the result

  • Running op=status again shows has_duplicate_uuids as false and load_failure_count at 0 or clearly reduced.
  • Assets that were missing reappear in the grid and in search results.

Tips

  • A failing individual check is returned in its own *_error field and does not fail the whole health check.
  • On load failures the Script Editor also prints 「⚠ 加载失败 N 个资产」 (failed to load N assets), which can be compared with the health result.
  • The toolbar refresh button is equivalent to rescanning the disk (op=reload) and also checks for leftover temporary directories.
  • fix_uuids rewrites asset IDs, so places that reference the old IDs such as favorites may need a manual review.
