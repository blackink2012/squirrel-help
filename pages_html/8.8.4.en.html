The plug-in finds Maya through two layers of ports: the backend port routes commands and Maya's commandPort provides the direct fallback; every Maya process is a separate instance.

Backend and instances

  • The backend listens on http://127.0.0.1:39002 by default; when that port is taken it switches automatically and writes the actual address into the endpoint file ~\.squirrel_asset_manager\broker_endpoint.json.
  • Each Maya registers as an instance named maya-<version>-<process id>. Tools act only on the instance bound to this conversation by default; cross-instance work must be allowed explicitly so multiple sessions are not confused.
  • The AI assistant and external MCP clients connect to the same backend but can each choose which instance to bind; AI search reads the current library's index directly and does not go through the backend.

Maya fallback ports

When the backend is unavailable the plug-in can talk to Maya's commandPort directly. Ports are assigned by version: 7001 for 2026, 7002 for 2025 and so on; with several sessions of the same version the later one falls back to the 7110–7129 range and records it in bridge_port.log.

Security boundaries

All ports bind 127.0.0.1 only and are never exposed to the LAN. But a commandPort is equivalent to an arbitrary-code-execution entry: do not forward it to the internet and do not leave it open on untrusted networks.

Confirming with several sessions

First list the instances to see which are online and then decide what to operate on; never rely on "whichever responds first", which is the usual cause of cross-session mix-ups.
