netstat 显示端口 LISTENING，不代表 Maya 活着；判活必须真投一条命令，看它答不答。

症状

  • 工具提示连接失败或超时，但 netstat 里对应端口仍在监听。
  • --ping 没有返回版本与场景，或连接被拒绝（WinError 10061）。
  • Maya 窗口看起来开着，但界面不响应，或前面挡着对话框。
  • 新启动的 Maya 没占用默认端口，客户端一直报「连不上」。

可能原因

原因判断方法处理
Maya 主线程卡死进程在、端口在监听，但命令超时或连接被拒确认后清理卡死实例
模态对话框挡住主线程Maya 窗口有崩溃恢复、报错或未保存提示先点掉对话框，再重试
崩溃报告器仍占用端口崩溃后端口还在监听，但没有正常响应按崩溃恢复流程处理
端口换到了备用段默认端口被同版本实例占用扫描 7110–7129 备用段
客户端只认固定端口实际实例在备用端口用自动发现或设置端口环境变量
端口被其他进程占用端口所有者不是 Maya换端口或结束占用进程

解决步骤

  1. 先看 Maya 窗口，如果有模态对话框，点掉后再执行一次探活。
  2. 运行 python maya_bridge.py --doctor，查看每个端口的 listening、responsive 与 verdict。
  3. 运行 python maya_bridge.py --ping，确认返回的是哪台 Maya、哪个场景。
  4. 运行 python maya_bridge.py --scan，确认实例是否落在备用段 7110–7129。
  5. 确认是卡死且不是模态框后，运行 python maya_bridge.py --doctor --kill-hung；它只清「监听但不应答」的实例。
  6. 没有可用实例时运行 python maya_bridge.py --doctor --launch，等它真正能应答。
  7. 客户端必须固定端口时，设置 SQUIRREL_MAYA_PORT 指向实际端口。

结果验证

--ping 返回「Maya 版本 | 当前场景」，--doctor 中对应端口显示 verdict=healthy，命令能正常往返。

仍不行怎么办

  • 查看 ~\.squirrel_asset_manager\bridge_port.log 最近的端口分配记录，确认是否反复退到备用段。
  • 检查 %TEMP% 是否有新的 MayaCrashLog*.dmp，判断是卡死还是已经崩溃。
  • 不要只凭 netstat 就杀掉进程；健康实例和用户的活一律不动。
  • 按 6.7.2「崩溃恢复三步」继续处理，或按 6.8.2「诊断流程」收集信息。
