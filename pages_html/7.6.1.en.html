When the imported materials or lights differ from the current renderer, the plug-in asks whether to convert; choosing No keeps the asset's original renderer nodes.

Symptoms

After importing an asset a 「材质与渲染器不匹配」 (material and renderer do not match) or 「灯光与渲染器不匹配」 (light and renderer do not match) dialog appears, saying the asset belongs to one renderer while the current renderer is another, and asks whether to convert to the current renderer's type.

Cause

The asset records the concrete node types from export time (commonly Arnold, V-Ray or Redshift). The current Maya's defaultRenderGlobals.currentRenderer differs, and creating the nodes directly would produce nodes another renderer cannot use.

Steps

  1. Confirm the current renderer and its plug-in are loaded so the conversion target type exists.
  2. Choose 「是」 (Yes): materials convert to the current renderer's default material and lights to the matching type; the original nodes are replaced.
  3. Choose 「否」 (No): nodes stay as the asset's original type, and you can right-click 「转换导入」 (Convert import) later to pick a target type.
  4. If the Script Editor says 「无 xxx -> yyy 的映射路径」 (no mapping path from xxx to yyy), a .mmap is missing; nodes stay as they are and nothing aborts with an error.

Verify the result

After conversion the node types in the Hypershade / Outliner belong to the current renderer; renders no longer report unknown nodes; scene materials or lights look right.

If it still fails

  • Check that the target .mmap is in Assets/material_mapper_presets or Assets/light_mapper_presets and named source type_target type.mmap.
  • Only Arnold, V-Ray and Redshift ask automatically; convert native Maya materials manually with the material conversion tool.
  • Right-click 「导入」 (Import) builds first and asks afterwards; double-clicking a .zlight converts directly to the current renderer without asking.
