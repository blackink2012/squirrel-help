dry_run

Of the current 146 commands, 106 declare dry_run_supported=true. With dry_run=true:

  • The library, scene and configuration are unchanged, and no rollback snapshot is written; the audit record is marked dry_run.
  • The command returns status="preview" whose content varies: move returns from / to for each node, batch_move_to returns the whole destination plan, and import commands return the list of files that would be created or copied.
  • dry_run can be a standalone parameter or a key inside params; the executor pulls the latter out and honors it.

Read-only commands do not support preview; they return current data directly.

undo

Thirty commands in the manifest declare undo_supported=true. Before executing, the executor calls snapshot_fn to record a snapshot, then completes it with snapshot_after_fn afterwards (for example, copy operations need the newly generated ids), and finally pushes it onto the in-memory UndoStack.

CoverageRollback method
Scene transforms, parenting, grouping, visibility, attributes, material assignment, zeroingInverse operation
Scene deletion delete_objectsMaya's own undo stack (snapshot marked maya_undo)
Library move, copy, rename, edit, delete, importRestore the original category from the snapshot, or delete newly created folders

When calling undo_last, steps=N rolls back the most recent N entries consecutively; dry_run=true only reports which entries would be rolled back. If one entry fails to roll back, its snapshot is returned to the top of the stack for a retry.

Warning: The UndoStack lives only in memory and is cleared when the plug-in reloads or Maya restarts. maya_run_python / maya_run_mel do not enter undo_last; back up the scene separately before using them.
