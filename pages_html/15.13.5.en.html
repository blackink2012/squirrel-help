One-line summary: connect Squirrel Asset Manager's capabilities (skill docs plus the MCP tool entry) to external AI tools such as Claude Code, Codex and Trae, so they know you have an asset library and Maya.

For an external tool to really do work, both halves are needed; with only one, "the model knows this exists but cannot call it":

  1. Skill landing: copying our skill docs into the other tool's skill directory;
  2. MCP channel: writing this plug-in's MCP entry into the other tool's configuration — that is what makes the squirrel_* tools mentioned in the skills actually exist.

That is why the window shows the state of the two halves separately for each tool.

How to open it

Settings → AI settings → the "External AI tools…" button.

Note: actions in this window persist on the spot (copying skills / writing the other tool's config) and do not follow the settings window's OK / Cancel semantics — clicking Cancel does not roll back an install already done.

A complete connection flow (Claude Code as the example)

  1. Settings → AI settings → External AI tools…;
  2. Click Detect again first and see whether the Claude Code card reads "not installed / not found" or is detected;
  3. Check the skill directory path; if it is wrong click Choose path… and pick its skill directory;
  4. Click Install skills → read the confirmation ("what will be overwritten, what will be written") → continue;
  5. Tick MCP channel → it writes into that tool's config (the original is backed up automatically and the status line shows connected plus the config path);
  6. Click Close;
  7. Start a new session in the external tool and ask it "what tools can I use in this project" to confirm it read the skills / tools.

What you see afterwards

  • The card badge changes from "skills not landed" to "skills in place (N)";
  • The MCP row becomes "connected (config file at the path below)";
  • The other tool's configuration directory gains our skill directory / config entry.

Risks and how to undo

  • Install skills overwrites: a same-named directory is deleted then copied. If you edited our skill content over there by hand, those edits are lost (the confirmation explicitly lists "N will be overwritten").
  • It writes the other tool's configuration file (when MCP is ticked). The original is backed up automatically and the status line shows the backup path; to undo, click Remove skills and delete the matching entry in the other tool's config, or restore from the backup.
  • Remove skills only deletes directories with the squirrel- prefix and never touches other tools' skills in the same directory.
  • Several untested tools (Cursor / Gemini CLI / Windsurf / Trae international and so on) may not take effect; confirm the directory really is their skill directory before installing.
