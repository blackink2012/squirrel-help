In one line: this group decides whether external processes may drive this software — every item is a permission switch, all off by default, enable the minimum you need.

Why it is its own group, all off

They are not ordinary preferences but permissions: once on, an external AI or MCP client can read and write your asset library and even make Maya execute code. All off by default so a fresh install never leaves an unattended execution entry.

What each of the five unlocks

The environment variable SQUIRREL_ENABLE_MAYA_EXEC=1 can force the universal channel on; the risk is higher, so it is not recommended.

First enabling a high-risk item: the risk confirmation

Going from off to on (the first time) opens 「AI 助手授权与风险确认」 (AI assistant authorization and risk confirmation) listing every risk; it only enables after you check the confirmation:

The dialog states:

  • No approval: every command runs directly, with no confirmation dialog;
  • Arbitrary Python: permissions equal the current system user, with read, write and delete access to any file on this machine;
  • Protections bypassed: the recycle bin's soft delete and library path restrictions are no technical barrier to arbitrary code;
  • System / Maya permissions: nodes, materials, animation and project settings can be changed, equivalent to you operating the scene by hand;
  • Damage risk: mistaken edits or deletions may be irreversible (soft deletes restore from the recycle bin and overwritten exports keep history, but hard deletes cannot be restored);
  • Cloud: with a cloud service enabled, thumbnails and prompts leave this machine and require separate consent (see 11.4.7).

The confirmation record is kept locally for later review; leaving the box unchecked keeps the universal execution channel off.

Recommendations

  • Enable only the one or two items the current task truly needs;
  • Keep everything off on managed or production machines;
  • Turn high-risk items off promptly after use, so the next start exposes no execution entry.
