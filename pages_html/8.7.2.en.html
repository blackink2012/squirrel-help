Documentation search runs lexical and semantic retrieval in parallel and fuses them with weighted RRF: lexical guarantees precision when you know the name, semantics catches you when you do not.

The four lexical layers

  1. Whole-string hit: the query appears verbatim in the original name or description, scoring highest.
  2. Multi-word AND: the query is split on whitespace and every word must appear in the name, description or flag / attribute summary.
  3. Synonym expansion: reads kb/aliases.json and maps "decimate" to polyReduce and "scatter" to MASH_Distribute.
  4. Ranking: by actionability tier, then score, then IDF weighting; alias hits on the name get another half tier.

The semantic path

The query is encoded into a vector, compared by cosine similarity against about 17,000 entry vectors and fused with the lexical results. The fusion constant RRF_K is 20, so one rank of difference weighs little, preventing an accidental single-path hit from overriding the other path.

When lexical finds nothing, semantic results are returned alone; when the query is exactly a name, that name is locked so fusion cannot push it out.

Fallback and diagnosis

  • Without a semantic index, with Ollama stopped or the model not pulled, it uses lexical only without reporting an error.
  • A failing semantic call trips a circuit breaker of about 60 seconds during which retrieval falls back to lexical.
  • Each result's match says keyword, semantic or both, which tells you which path caused a problem.
