语义搜索是可选增强，不可用时会自动退回词法搜索，不会让搜索功能完全失效。

症状

  • 搜索还能出结果，但只按字面匹配，口语化描述搜不到目标资产。
  • 状态里显示 available=false，并带有「没有索引」「Ollama 连不上」或「熔断」等原因。
  • 第一次搜索明显变慢，随后一段时间又正常，或一直提示语义不可用。
  • 索引已经建好，但设置或环境变量换过模型后突然失效。

可能原因

原因判断方法处理
设置项 ai_asset_semantic 被关掉app_settings.json 里 ai_asset_semantic 为 false，状态原因会直说「已在设置里关闭」把它改回 true（当前设置界面没有这个开关，改配置文件或用命令 settings_set）
资产库索引不存在库目录下没有 .squirrel_ai_index\<official / ollama> 或 meta.json同步或重建资产索引
Ollama 没有安装或没有启动状态提示服务连不上安装并启动 Ollama
嵌入模型没有拉取ollama list 里没有对应模型拉取 embeddinggemma-2:740m
最近一次调用失败触发熔断状态提示冷却秒数等待冷却结束，或把冷却环境变量设为 0 立即重试
环境变量指定的模型与索引不一致状态提示模型不匹配去掉环境变量，或按该模型重建
宿主缺少 numpy提示仍可用但召回窄安装 numpy，或接受降级结果
索引放在共享盘/同步盘同一后端的索引被其他机器并发写入把索引改到本机本地目录（不同后端已按 official/ollama 分家，不会互相覆盖）

解决步骤

  1. 打开「设置 → AI」，先做一次 AI 依赖检查，确认 Ollama 与嵌入模型的状态。
  2. 在终端执行 ollama list，确认服务在运行且模型已拉取；缺失时执行 ollama pull embeddinggemma-2:740m。
  3. 确认语义检索的总开关没被关掉：它对应配置键 ai_asset_semantic（默认开），设置界面里目前没有这个开关 —— 只能改 ~/.squirrel_asset_manager/app_settings.json，或让 AI 助手执行命令 settings_set(updates={"ai_asset_semantic": true})（该命令是高风险级，会先要确认）。同一组里还有 ai_asset_semantic_sync（默认开，关掉后只在索引不存在时建一次）。
  4. 资产索引缺失或损坏时，执行 python tools/asset_index.py --sync；需要全量重建时用 --rebuild。
  5. 检查是否设置了 SQUIRREL_EMBED_MODEL 等环境变量；不要让查询模型与索引模型不一致。
  6. 索引目录改到本机磁盘后，重新打开插件窗口让设置生效，再搜索一次。

结果验证

asset_semantic_status 返回 available=true，搜索结果的 match 字段出现 semantic 或 both，口语化查询能命中目标资产。

仍不行怎么办

  • 先用 mode=keyword 保证搜索可用，再单独排查语义链路。
  • 查看 asset_semantic_status 的 reason 与 index_dir，确认缺的是索引、模型还是服务。
  • 首次查询可能因模型冷启动超过 20 秒超时，之后再试一次；模型常驻后查询会快很多。
  • 按 4.5.9.1「AI 不可用」和 4.8.4.1「AI 依赖检查与安装」继续排查。
