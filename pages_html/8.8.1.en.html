MCP is the standard channel through which external AI tools call the plug-in's capabilities; installing the skills alone is not enough — the tools the skill text refers to must really exist.

Two servers

NamePurposeDepends on Maya
squirrel-assetsSearch assets and drive Maya / Blender scenes, imports and exportsNeeds a live instance
maya-kbSearch the offline Maya knowledge baseNo, works without Maya running

Both start over stdio: in source form python mcp\squirrel_mcp_server.py, and packaged builds are launched by the main program with sentinel arguments. squirrel-assets also writes --broker-url and --instance-id, with the backend at http://127.0.0.1:39002 by default.

Which tools are exposed

Not every command is exposed, only a high-frequency allowlist covering scene, assets, rendering and execution; the command list is always fetched live from the backend's /commands and never hard-coded. High-risk commands (such as running Python) are in the allowlist too, and callers should preview before running.

How to attach it

In Settings → AI 设置 (AI settings) → 外部 AI 工具 (External AI tools) group → 外部 AI 工具… (External AI tools…) check MCP for the target tool and the plug-in writes the entry into that tool's configuration file; when there is no configuration it can safely write, copy the snippet and paste it by hand.

Boundaries

The MCP entry never connects to Maya directly and never imports maya; it only talks to the local backend. Before writing another tool's configuration it backs it up, refuses to write when parsing fails and only adds or removes its own entries.
