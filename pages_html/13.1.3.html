启动报错先看 Maya 脚本编辑器里的完整 traceback，它通常能直接指出缺失模块、旧副本、权限或授权问题。

症状

  • 点击插件入口后没有窗口，或窗口一闪就关闭。
  • 脚本编辑器出现红色 traceback，包含 ImportError、AttributeError、PermissionError 等。
  • 窗口能打开，但状态行、分类树或 AI 面板初始化失败。
  • 启动时提示 sq_license 不可用，进入只读模式，功能受限但程序没有崩溃。

可能原因

原因判断方法处理
包或子模块找不到traceback 顶部是 No module named ...按 6.1.1「插件未加载」检查安装路径与 userSetup.py
加载了旧副本或半成品目录sq.__file__ 不在安装目录，或目录里只有 Assets\删除旧副本，重新安装
核心模块 ABI 不匹配报扩展模块加载失败按 6.1.2「版本与 ABI 不匹配」处理
授权模块缺失日志出现 sq_license 不可用程序进入只读；确认安装包完整，或按授权页激活
安装目录没有写权限traceback 指向创建目录、写配置或写日志恢复目录权限，或换到用户可写位置
旧配置/旧缓存与新版本冲突报错集中在设置、索引或分类加载备份配置后重置对应缓存，再重启 Maya

解决步骤

  1. 打开 Maya 脚本编辑器，清空输出后重新点击插件入口，复现一次。
  2. 复制 traceback 的第一行错误和最后几行调用栈，不要只截「出错」两个字。
  3. 执行 import squirrel_asset_manager as sq; print(sq.__file__)，确认实际加载的是哪一份。
  4. 如果是模块缺失或旧副本，按 6.1.1「插件未加载」重新安装；如果是 ABI 错误，按 6.1.2「版本与 ABI 不匹配」换包。
  5. 如果只在 AI、桥接或状态行初始化时报错，检查 ~\.squirrel_asset_manager\broker_boot.log 与 bridge_port.log。
  6. 修改后完全重启 Maya，再验证一次。

手动启动（启动脚本没生效时）

如果工具架、状态行都点不开，但安装目录是完整的，可以在 Maya 脚本编辑器（Python）里手动跑一遍启动代码。

先确认自己的安装目录（要填的是「包含 squirrel_asset_manager 文件夹」的那一层）：

安装方式默认位置
EXE 安装（含 Maya 集成）安装向导里选择的目录，默认 %LOCALAPPDATA%\SquirrelAM；SquirrelAssetManager.exe 与 squirrel_asset_manager\ 都在这一层

判断标准：该目录下能看到 squirrel_asset_manager 文件夹，里面有 __init__.py 与 ui\main_window.py。如果插件以前能启动，也可以在脚本编辑器执行 import squirrel_asset_manager as sq; print(sq.__file__)，把结果末尾的 \squirrel_asset_manager\__init__.py 去掉，剩下的就是安装根目录。

把路径填到下面代码的 INSTALL_DIR（保留 r"..." 的原样字符串写法，路径里的反斜杠不用转义）；留空则按上表默认位置自动检测：

import os
import sys
import maya.cmds as cmds

# ① 自定义安装目录：只改这一行。填「包含 squirrel_asset_manager 文件夹」的目录，
#    例如 r"D:\Tools\SquirrelAM"；留空 = 按默认位置自动检测。
INSTALL_DIR = r""

# ② 整理候选目录：填了只认填的，没填就自动找
app_dir = os.path.normpath(cmds.internalVar(userAppDir=True))
local_appdata = os.environ.get("LOCALAPPDATA") or ""
if INSTALL_DIR.strip():
    candidates = [os.path.normpath(INSTALL_DIR.strip())]
else:
    candidates = [
        app_dir,                                      # 旧版脚本安装：%MAYA_APP_DIR%
        os.path.join(app_dir, "scripts"),             # 更早的脚本安装
    ]
    if local_appdata:
        candidates += [
            os.path.join(local_appdata, "SquirrelAM"),            # 独立版默认
            os.path.join(local_appdata, "SquirrelAssetManager"),  # 独立版旧默认
        ]
# 也允许直接把 …\squirrel_asset_manager 这一层填进来
candidates += [os.path.dirname(p) for p in list(candidates)]

install_root = next(
    (p for p in candidates
     if os.path.isfile(os.path.join(p, "squirrel_asset_manager", "ui", "main_window.py"))),
    "")
if not install_root:
    raise RuntimeError("没找到 squirrel_asset_manager，请把包含它的目录填到 INSTALL_DIR")
if install_root not in sys.path:
    sys.path.insert(0, install_root)

# ③ 清掉早先被缓存的空命名空间包
pkg = sys.modules.get("squirrel_asset_manager")
if pkg is not None and not getattr(pkg, "__file__", None):
    for name in [n for n in list(sys.modules)
                 if n == "squirrel_asset_manager"
                 or n.startswith("squirrel_asset_manager.")]:
        del sys.modules[name]

# ④ 打开主窗口（重复执行只会召回已有窗口）
from squirrel_asset_manager.ui.main_window import MaterialLibraryWindow
MaterialLibraryWindow.show_window()
print("已从 %s 启动" % install_root)

执行结果这样判断：

  • 窗口正常打开：说明插件本体没问题，只是 userSetup.py 启动段没生效。可把上面代码追加到当前版本的 Documents\maya\<版本>[\<语言>]\scripts\userSetup.py 末尾，或重新运行安装器写入启动段（见 6.1.1「插件未加载」）。
  • 仍报 No module named 'squirrel_asset_manager'：INSTALL_DIR 没填或填错了层级；按上面的判断标准核对，并确认该目录下有完整的包（不是只剩 Assets\）。
  • 报扩展模块或 DLL 错误：ABI 不匹配，按 6.1.2「版本与 ABI 不匹配」换包。

手动执行只在当前 Maya 会话有效；要每次启动都自动就绪，还是需要 userSetup.py 里的启动段。写进 userSetup.py 时请保留 INSTALL_DIR 的填写——自动检测只覆盖默认位置，自定义目录不填就找不到。

结果验证

插件窗口正常出现，脚本编辑器不再出现同类 traceback，分类树与状态栏能完成初始化。

仍不行怎么办

  • 先用空场景启动，排除场景本身或第三方插件造成的干扰。
  • 暂时禁用其他启动脚本，确认不是多个工具同时改写 userSetup.py。
  • 按 6.8.2「诊断流程」收集信息；反馈时附完整 traceback、Maya 版本和安装目录树。
  • 涉及授权的报错不要提交完整许可证文件或密钥，只提供状态与错误码。
