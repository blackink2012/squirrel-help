Every top-level category has an automatically created 「自定义」 (Custom) sub-category (folder name AAAcustom) that receives assets which cannot live directly in a top-level category.

Why it exists

Top-level categories (sub-library roots and custom top-level categories under the library root) cannot hold .zasset packages directly. Every create or import path resolves the landing spot first: if the target is a top-level category, it is redirected to that category's AAAcustom and the asset metadata records that sub-category. This keeps the category index from containing "assets hanging directly off a sub-library root" and avoids self-referencing parent / child nesting such as materials/materials.

Rules

  • 「自定义」 (Custom) cannot be deleted: there is no delete item in its context menu, and even if a delete is triggered it only reports that this sub-category cannot be deleted.
  • It can be edited like an ordinary category: change its display name, create sub-categories and receive dropped assets.
  • Importing assets with a top-level category selected puts them below it, not in the top-level category itself.

How to use it

Treat 「自定义」 (Custom) as the default catch-all of its top-level category: assets imported into the top-level category land here. For finer structure, create sub-categories below it and move assets into them.

Verify the result

After importing assets with a top-level category selected, expanding that top-level category should show the assets inside its 「自定义」 (Custom) sub-category.
