When library health looks wrong, check the four criteria of library_health first: whether it is loaded, asset and category counts, duplicate UUIDs, and the load-failure list.

Symptoms

  • The asset total does not match the number of .zasset folders on disk.
  • Assets clearly exist in the library directory but cannot be found in the plug-in grid.
  • Favorites, versions or category references are scrambled and do not recover after a rescan.
  • library_health returns is_loaded false, has_duplicate_uuids true, or load_failure_count greater than 0.

Possible causes

CauseHow to tellAction
The library did not loadis_loaded is false and the asset count is 0Check the library path and permissions, then rescan
Index cache is staleThe category tree or asset count disagrees with diskClear the cache and reload
Duplicate UUIDshas_duplicate_uuids is truePreview, then fix the duplicates and rescan
Asset metadata corruptedAn entry in load_failures carries a reasonRestore from backup, or re-import that asset
Configuration disagrees with diskSub-library or category counts do not line upRe-read the configuration
Several people or machines edit the library at onceThe index lags or entries overwrite each otherKeep the index in a local directory and rebuild when necessary

Steps

  1. Run library_health with op=status and record the library root, whether it is loaded, asset and category counts, duplicate ids and load-failure count.
  2. Read the reason of each asset in load_failures to see whether a file is missing, metadata is corrupted, or the version is incompatible.
  3. For cache problems run op=clear_cache first, then op=reload, so the plug-in rebuilds the index from disk.
  4. For configuration problems run op=reload_config to re-read sub-library and category configuration.
  5. For duplicate UUIDs, preview with op=fix_uuids plus dry_run=True before running it for real; a rescan happens automatically afterwards.
  6. If one asset's metadata is corrupted, back up that .zasset first, then restore from backup or delete it and import again.

Verify the result

Running op=status again shows is_loaded true, has_duplicate_uuids false and load_failure_count 0, with the asset count matching disk.

If it still fails

  • After fixing duplicate UUIDs, places that stored the old ids (such as favorites) may need rechecking.
  • Back up the whole asset library before going through the failing assets one by one; never bulk-delete library directories.
  • When several machines share a library, put the semantic index in a local directory so index files do not overwrite each other.
  • When reporting, include the status return of library_health, the load-failure list and the most recent rescan log.
