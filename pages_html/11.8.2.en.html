An alias is a keyword in the file name used to decide which PBR channel a texture belongs to.

What it does

Settings → Texture suffixes lists the texture types on the left and the alias list for the selected type on the right, one per line. The data comes from texture_type_rules in Assets/preset/pbr_mapping.json; the aliases array of each entry is exactly this list.

Values and defaults

  • The types are defined by the JSON. Currently they include baseColor, normal, roughness, metallic, ao, arm, orm, emissive, height, opacity, clearcoat, clearcoatRoughness, specular, subsurface, anisotropy, ior.
  • Each type can have several alias lines. An alias is a keyword without the extension. For example normal contains nrm, n and normal, so crate_n.png is recognized as a normal map.
  • Type matching priority comes from priority in the JSON; the UI only edits aliases.

Scope of effect

  • It affects texture channel detection in PBR-to-asset conversion and in material creation.
  • It only matches file name keywords: it does not rewrite files, and it does not change texture paths in assets that already exist.

When to change it

When your naming convention differs from the default aliases, for example when roughness is written _r and metallic is written _m.

Steps

  1. Open Settings → Texture suffixes and unlock if necessary.
  2. Select a type on the left, then edit alias lines on the right.
  3. Click Apply or OK to write back to pbr_mapping.json.

Verify the result

Run PBR-to-asset conversion with a texture named after the new alias; the texture should land in the matching channel.

Tips

The Restore defaults button on this page re-reads pbr_mapping.json from disk so you can discard unapplied edits. It does not generate a factory copy.
