The dependency file import policy decides whether linked files such as caches, proxies and references are copied into the project on import.

Effect

It controls where files under .zasset/deps/ end up in Maya and which paths they use.

Values and defaults

OptionBehavior
Copy into the projectCaches and proxies are copied to {project}/cache/squirrel_asset/{asset name}_{last 4 of ID}/; reference files go to {project}/references/squirrel_asset/...
Current asset directory (default)No copying; points directly at deps/ inside the .zasset
Source file directoryRewrites nothing and keeps the original paths recorded at export
  • The preset file currently holds asset_directory; when that key is missing the code falls back to copy_to_project.

Scope

  • It applies to file-based nodes such as Alembic, gpuCache, proxies, Maya references and volumes when importing geometry, scenes and animation.
  • It only changes the paths after import and never modifies the asset package.
  • Scanning always runs even without redirection, and missing dependencies are recorded in the asset metadata and the log.
  • It is stored as dependency_import_policy in config.json.

When to change it

  • The asset must be delivered to another machine, or the project must be self-contained: choose 「拷贝到项目」 (Copy into the project).
  • Single-machine use where dependencies live with the asset: keep 「当前资产目录」 (Current asset directory).
  • Still in the original working environment and wanting to keep referencing it: choose 「源文件目录」 (Source file directory).

Tips

Warning: 「源文件目录」 (Source file directory) relies on the original absolute paths; after moving machines the paths break and import reports missing dependencies.

Tip: reference files land in a different place from ordinary caches, going into the project's references/ and cache/ areas respectively.
