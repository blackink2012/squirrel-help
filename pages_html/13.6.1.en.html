The plug-in shows the window first and loads the asset library in the background, so slow startup is usually slow library scanning, index cache or disk reads, not UI construction.

Symptoms

  • The window appears quickly, but a loading indicator stays in the middle while the category tree and thumbnails take a long time.
  • The first launch is clearly slower than the second.
  • One particular library is very slow while the others are fine.
  • The asset count in the status bar does not update for a long time, but Maya itself is not frozen.

Possible causes

CauseHow to tellAction
The asset library is very largeThousands of assets; scan time grows with the countSplit into several libraries, or reduce the asset count per library
No index cache on the first launch.squirrel_index_cache.json does not exist under the library root yetWait for the first scan; the second launch hits the cache
The library is on a network or sync driveThe directory is on a NAS, cloud drive or auto-sync folderMove the library to a local disk
Index cache incompatible with the current versionThe log says "index cache incompatible, falling back to a full scan"Clear the cache and let it rebuild once
The first read of many asset descriptionsThe first sync after a restart reads many meta.json filesWait for it to finish in the background; the description cache is used afterwards
Many thumbnails loading at onceThe first screen decodes many images simultaneouslyWait for async loading, or reduce the number on the first screen
The AI index warms up in the backgroundThe status shows warming upWarm-up does not block search; just wait for it

Steps

  1. Check whether the window has appeared, then decide whether the UI or the data loading is slow.
  2. Look at the [MaterialManager] log in the Script Editor to see whether it hit the cache or is doing a full scan.
  3. Move the asset library to a local disk; avoid network drives and real-time sync folders.
  4. On the first launch wait for the scan to finish, confirm .squirrel_index_cache.json was created, then restart and compare the second run.
  5. For a broken cache, clear it with library_health op=clear_cache and let it rebuild once.
  6. When there are too many assets, split by sub-library or project to reduce the scale of each load.

Verify the result

The second launch is clearly faster than the first, the category tree and first-screen thumbnails appear shortly after the window opens, and the status bar count is correct.

If it still fails

  • Record the library's asset count, disk type (local/network), and cold and warm startup times.
  • Compare with an empty library; if an empty library is also slow, the bottleneck is not asset scanning.
  • Check whether several Maya instances load the same library at once, or sync software is scanning the library directory.
  • Continue with 6.6.2 "Stuttering and memory" and 4.1.12.2 "Index rebuild".
