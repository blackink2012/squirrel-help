Import namespace decides which namespace freshly imported nodes land in. It is the isolation layer that stops an import from clashing with nodes already in the scene.

Where it lives, and the default

  • Location: Settings → General → Import namespace (the checkbox "Create a namespace automatically on direct import (named after the asset)");
  • Default: ticked (import_namespace is true in config.json; a missing key is treated as on).

When it is on (default)

  • The namespace name comes from the asset name: characters other than letters / digits / CJK / underscore become _, and leading or trailing underscores are trimmed;
  • If the name starts with a digit it is prefixed with ns_ (Maya does not allow namespaces starting with a digit);
  • If the scene already has that namespace, _1, _2… is appended;
  • Result: the whole asset forms one group of nodes you can select, hide or delete by namespace, and it never fights with same-named objects already in the scene.

When it is off

  • New nodes go straight into the root namespace :;
  • Nodes that clash with existing ones are renamed by Maya (pCube1, pCube2…), so you can no longer tell which nodes came from this import.

Scope

  • It only affects later imports: save, and the next import follows the new rule; nodes already imported are not moved into or out of a namespace;
  • It applies to direct imports (geometry / scenes / animation / caches and proxies); the right-click Add reference has its own namespace rule (asset name plus _1 / _2) and is not controlled by this switch;
  • It changes node placement only — not the asset package, texture paths or dependency paths;
  • Stored as import_namespace in config.json.

Notes

Tip: To get rid of that prefix, untick the option and click Apply / OK; no plug-in restart is needed.

Warning: With it off, clashing nodes are silently renamed by Maya, so finding "what this import brought in" by name becomes much harder; keep it on when importing a batch of assets.
