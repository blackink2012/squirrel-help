The encoding command compiles a set of frame images into a GIF or a video, with the output format decided by the file extension.

Prerequisites

  • The frame files exist and are named consecutively by frame number (such as frame_0001.png).
  • An .mp4 output needs ffmpeg; the plug-in ships bin/ffmpeg.exe. A .gif output falls back to Pillow when ffmpeg is missing.

Steps

  1. Call encode_sequence with image_dir for the frame directory, or pass an explicit files list.
  2. Set the output file output: .mp4 (.mov / .mkv / .webm also work) or .gif.
  3. Set fps (24 by default); to shrink a GIF use max_width to scale the frames.
  4. When frame names vary, set the scan pattern with pattern, frame_*.png by default.

Verify the result

The command succeeds and the output file exists; open it in a player and confirm the frame order and duration. On cancel the partial file is deleted, and errors state whether it was NO_ENCODER or FRAMES_NOT_SEQUENTIAL.

Tips and warnings

  • Frame names must be consistent and consecutive; with gaps ffmpeg would produce a wrong order, so the command reports FRAMES_NOT_SEQUENTIAL instead of forcing an encode.
  • When neither ffmpeg nor Pillow is available it reports NO_ENCODER honestly and gives the frame directory, never pretending to succeed.
  • Encoding is pure file and subprocess work that never touches Maya, so it can run on a worker thread and still supports progress and cancel.
  • Frame rate and total frame count decide the duration; pair GIF output with max_width to keep the file size reasonable.
