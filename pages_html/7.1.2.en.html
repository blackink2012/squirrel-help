A material asset records a concrete node type, and whether it can be rebuilt directly depends on the current Maya having the matching renderer plug-in loaded.

Common mappings

Steps

  1. In Maya confirm the current renderer (defaultRenderGlobals.currentRenderer) and that the matching plug-in is loaded.
  2. In the library check the material asset's node_type and renderer and use the table above to judge whether the target machine can create it directly.
  3. Double-click to import, or right-click 「转换导入」 (Convert import) and choose a material type common for the current renderer.
  4. If the plug-in is not loaded or this version has no such node type, deleting that material node fails; load the plug-in and retry.

Verify the result

After import the matching type appears in the Hypershade and the attribute editor title shows the correct node type; the material created by a double-click matches the current renderer.

Tips

  • Whether import converts automatically depends on the entry:
    • Double-clicking a zmetal: converts straight to the current renderer's default material, without a confirmation;
    • Right-click 「导入」 (Import): builds the asset's original material first and then asks once for the whole batch (all materials in one asset are asked once, never per material), converting only after confirmation;
    • Other formats (such as ma) ask before converting whether double-clicked or right-clicked.
  • Automatic conversion only recognizes Arnold, V-Ray and Redshift; native Maya materials and the current renderer's materials are not converted, so use the material conversion tools manually when needed.
  • Importing the same asset on machines with different renderers may yield different node types; that is the result of conversion, not a damaged asset.
