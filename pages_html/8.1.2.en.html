By default everything runs locally: Ollama provides embedding and vision capability and the index files live in the asset library or a local directory you choose. Requests only reach a provider when you actively configure a cloud model.

The local part

  • Ollama: a local service, http://127.0.0.1:11434 by default, which the plug-in uses for embeddings and image understanding.
  • Embedding model: embeddinggemma-2:740m (768 dimensions) by default, shared by the asset text index, the Maya documentation index and the image index.
  • Vision chat model: AI asset analysis and the "image to description" step of image search need a chat model that can see images; the dependency check recommends qwen3.5:9b (about 5–6 GB), and any other pulled vision model also works.
  • Image sidecar: a separate venv installing only numpy and Pillow (about 30 MB); image vectors are still encoded by the Ollama embedding model.
  • dsh: the AI assistant runtime, which manages its own model credentials.

The cloud part

Settings → AI → 全局大模型（默认） (Global model (default)) offers Ollama (local), DeepSeek, Qwen (Alibaba Cloud DashScope), Zhipu (BigModel), OpenAI and Custom (OpenAI compatible). AI analysis uses it by default, and 「使用全局大模型」 (Use the global model) at the top of the AI search preview panel reads it as well.

AI search has its own configuration (the settings at the top right of the preview panel) and by default calls no large model, doing local vector retrieval only.

How the work is split

  • Everyday asset search and search by image: local, fast and requiring no key.
  • Thumbnail analysis and stronger semantic understanding: a local vision model or a cloud configuration.
  • Long conversations and cross-tool orchestration: dsh or an external AI tool.

Whether a cloud model supports images varies by provider, and the configuration box shows the matching hint.
