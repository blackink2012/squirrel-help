The context menu configuration is not one global set but one per sub-library, independent of each other.

Effect

The list on the left shows every entry of sub_libraries in config.json, including the 11 built-in sub-libraries (materials, models, lights, textures, scenes, HDR, dynamics, images, audio, animation data, node trees) and custom sub-libraries. Selecting one shows that sub-library's current checks on the right.

Values and defaults

  • Each menu item is true / false for that sub-library.
  • Factory presets are stored per sub-library in context_menu_preset.json. For example models have 「格式转换」 (Format conversion) on by default, and HDR has 「创建环境光」 (Create environment light) and 「指定贴图到材质」 (Assign texture to material) on.
  • Custom sub-libraries and categories not registered in the preset read the default section: shared items are true and category-specific items are false.
  • When switching sub-libraries the checks of the current page are held in memory, and only 「应用」 (Apply) writes them all.

Scope

  • The context menu uses the section matching the asset's sub-library (the category type), so the same asset can show different menus under different sub-libraries.
  • Category-specific items are greyed out in sub-libraries where they do not apply, with notes such as 「（仅 材质/贴图）」 (materials / textures only) appended; their checked value is kept and becomes usable again in the right sub-library.
  • Custom sub-libraries can only use shared items; category-specific items are always greyed out for them.

When to change it

When different asset types should have different menus, for example showing 「格式转换」 (Format conversion) in the model library and hiding it in the material library, or keeping only import and open folder for a custom sub-library.

Tips

An unregistered category never ends up with "no menu": it inherits the default section, so the context menu is never missing items.
