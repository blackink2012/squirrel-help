The menu only calls main() / run() without arguments; when parameters or structured results are needed, use the PARAMS / RESULT convention of the command channel or the script browser.

Entries and parameters

  • The menu and the command channel resolve entries the same way: main() → run() → run once as __main__ when the source contains if __name__ == "__main__".
  • The menu calls main() / run() without arguments.
  • The quicktool_run command tries fn(params) when params is given; when the entry does not accept arguments (raising TypeError) it falls back to fn().
  • When only main / run exists the module body is not executed again, so top-level side effects never run twice.

The PARAMS / RESULT convention

A script-style entry can read and write two conventional variables:

PARAMS = globals().get("PARAMS") or {}
DRY_RUN = bool(PARAMS.get("dry_run", False))

def main():
    # do the work here; for writes prefer dry_run first and return before / after values
    return {"status": "ok", "updated": 0}

RESULT = main() if not globals().get("SKIP_RUN") else None
  • PARAMS: the JSON object passed by the script browser's "run with parameters…" or by the command channel.
  • RESULT: the script result; the script browser prints a summary and the command channel puts it into its return value.
  • MEL has no PARAMS / RESULT convention, so print the important results.

Return value shape

  • The command channel can safely return None, booleans, numbers, strings, lists and dictionaries.
  • Nested dictionaries / lists keep only the first 30 items; other objects are turned into repr and truncated to 300 characters, so never return unserializable objects such as Qt widgets.
  • GUI tools normally have no meaningful return value; the command channel only reports opened: true, meaning the window opened and the work is not finished.

Verify the result

  1. Call quicktool_run with dry_run=true first to confirm the entry is resolved correctly.
  2. After a real run check status, entry and result in the return value.
  3. Run the same script in the script browser; the status bar should show the elapsed time and the Script Editor should show the RESULT summary.

Notes

  • The menu path never injects PARAMS, so logic that depends on parameters must also run safely with defaults.
  • For long-running or cancellable work, provide your own progress and cancel mechanism inside the script.
