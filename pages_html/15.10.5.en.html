One-line summary: the top two checkboxes in the right column decide whether, besides the asset itself, textures and scene dependencies are copied into the package.

Item-by-item details

ControlTypeEffectSuggested valueWhat filling it in wrongly does
Collect caches / proxies / references loaded in the sceneCheckboxCopies caches (.abc and so on), proxies (.ass/.vrmesh/.rs) and referenced files into the package's deps/Tick it when delivering "open and it works" assetsOff: only a dependency list is recorded, no files are copied, so opening the asset on another machine misses references
Textures textures/CheckboxCollects the textures used by materials into the package's textures/Ticked by default; almost always keep itOff: the asset holds no textures, and materials are empty or lost after import

The two switches are independent: textures only is fine, associated files only is fine, and both give the most complete self-contained asset (and the largest package).

Scanning and collecting are different things

  • Scanning always happens: on export the plug-in always scans which external files the asset depends on, which are missing and which lie outside the allowed scope, and records the result in the export log.
  • Only collecting copies: files are really copied into the package only when Collect caches / proxies / references is ticked; otherwise only a list is kept.
  • So a log line such as "collect_associated=False → list only, no copy" is normal behavior, not a failure.

Where the dependency strategy is changed

Once textures and dependencies are copied into the package, path handling is decided by settings, not this dialog:

SettingLocationEffect
Texture import strategySettings → Asset libraryOne of "copy into the project / put in the asset directory / keep the source path"
Dependency import strategySettings → Asset librarySame options, applied to caches / proxies / references

See 4.8.3.3, 4.8.3.4.

A complete example (adding a material with its textures)

  1. Select the material node in Maya.
  2. Open the export dialog and confirm Textures textures/ is ticked in the right column.
  3. If the material also references external models / caches (for example it sits on a referenced model), tick Collect caches / proxies / references loaded in the scene too.
  4. Tick Material preset .zmetal (see 8.10.6).
  5. Click Create asset and finish the capture.
  6. Verify: right-click the new asset → Asset details and check the included formats and size; a clearly larger size means the textures came in. Details are in 8.11.1.

Troubleshooting

SymptomCauseWhat to do
The material has no textures after importTextures textures/ was unticked on export, or the texture paths were outside the supported scopeRe-export with textures ticked, or bring the export back with Update asset → Append format
The package is hugeCollect associated files was ticked and a whole cache set was copied inFor such assets turn Collect associated files off and manage caches separately
References are lost after moving machinesOnly scanned, never collectedRe-export with Collect caches / proxies / references ticked
The log says "list only, no copy"Collect associated files is off (by design)Tick it when you need a self-contained asset
