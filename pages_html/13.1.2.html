核心模块按 Python ABI 编译成多份 .pyd 共存；Maya 的 Python 版本与 .pyd 的 cp 标签对不上时，导入会失败。

症状

  • 打开插件或导入核心模块时报 ImportError、DLL load failed while importing ... 一类的扩展模块错误。
  • 同一份安装在某几个 Maya 版本正常，在另一个版本打不开。
  • 更新后只有部分功能报错，界面能开但导入、导出或材质相关操作失败。
  • 源码目录里同时有 .py 和 .pyd 时，本机优先加载 .py，问题可能只在发布版出现。

可能原因

原因判断方法处理
缺少当前 Maya 的 ABI 版本核心目录里没有对应 cp 标签的 .pyd换含该 ABI 的安装包，或用源码运行
安装包与 Maya 版本不配套cmds.about(version=True) 与 .pyd 标签不一致按下表确认对应关系
混入了别的 Maya 的编译产物目录里出现来源不明的 .pyd重新安装完整包，不要手工改名
只含 .pyd 的发布版缺文件核心模块只有部分 .pyd重新获取完整发布包
热重载后仍用旧模块改了源码但行为没变完全重启 Maya，而不是只刷新界面

ABI 对应关系

.pyd 标签Maya 版本Python
cp37Maya 20223.7
cp39Maya 20233.9
cp310Maya 20243.10
cp311Maya 2025 / 20263.11
cp313Maya 20273.13

解决步骤

  1. 在 Maya 脚本编辑器执行 import maya.cmds as cmds; print(cmds.about(version=True))，确认 Maya 年份。
  2. 执行 import sys; print(sys.version_info)，确认 Python 主次版本。
  3. 查看核心模块目录，确认存在与 Python 版本对应的 .pyd（例如 Maya 2026 需要 cp311）。
  4. 标签不匹配时，换用匹配的安装包；不要跨版本重命名 .pyd。
  5. 本机调试可保留 .py 源码，包入口会优先加载 .py；发布版只带 .pyd 时则必须匹配 ABI。
  6. 替换文件后完全退出并重启 Maya。

结果验证

插件能打开，import squirrel_asset_manager.core.manager 等核心模块不再报扩展模块错误。

仍不行怎么办

  • 把 cmds.about(version=True)、sys.version_info 和报错模块名一起记录下来。
  • 确认安装目录里没有被旧版本残留的 .pyd 覆盖。
  • 如果只有某个核心模块失败，检查该模块是否在安装包中缺失，而不是继续改环境。
  • 仍无法判断时，按 6.1.3「启动报错」抓取完整 traceback 后反馈。
