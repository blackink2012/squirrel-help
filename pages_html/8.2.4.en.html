Install failures are usually network, permission or Node version problems; read the report and logs first, then fix only the step that failed instead of reinstalling everything.

Symptoms and fixes

Ollama did not install: confirm the ollama command exists, or install it manually from ollama.com and rerun the one-click install. Automatic install on Windows relies on winget and fails when a policy blocks it.

The service did not start: confirm port 11434 is free, run ollama serve manually and then open http://127.0.0.1:11434/api/tags. If the system or environment sets a proxy (HTTP_PROXY / HTTPS_PROXY) without putting 127.0.0.1 in NO_PROXY, even loopback requests are intercepted.

Model pull interrupted: rerun the one-click install, which skips finished steps. On a slow network switch mirrors or try later.

Image sidecar half installed: a venv without numpy / Pillow counts as incomplete. Rerun the install, or run python tools\asset_vision_env.py --install --self-check.

Index build failed: mostly Ollama is not running or a model is missing. Run the dependency check first and confirm the library path exists; on the command line python tools\asset_index.py --status and --doctor show the reason.

dsh install failed: close any open AI panel and retry so files are not locked; Node must be ^22.19 || >=24.

Reading the logs

  • AI dependency install: %TEMP%\squirrel_asset_manager\ai_install.log
  • dsh install: <plug-in directory>\dsh_home\dsh_install.log
  • dsh startup: <plug-in directory>\dsh_home\squirrel_web_<instance>.log

If it still fails

Report the report, the last 40 log lines and the OS version together; do not delete a half-built venv or index directory by hand — rerunning the install overwrites and repairs them.
