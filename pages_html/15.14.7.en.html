One-line summary: export the material network you tuned in one scene into files (.zmetal or MA+JSON), then import it into another scene and have it assigned to the matching models automatically.

It solves "materials must move between scenes / machines". The two tabs are two output formats with the same capability in different shapes:

TabOutputGood for
Full-spectrum editionThe complete material network → .zmetal (optionally with .ameta metadata, .mcm object mapping and a texture folder)Moving only materials, using the plug-in's own format
MA+JSON editionThe material network → a Maya .ma script plus .json dataWhen the other side has no plug-in / wants native MA

The window is titled "Material import/export tool", with the two tabs at the top.

Common prerequisites

  • Select what to export in the scene first (models or materials both work; see the options below);
  • Exported files are written to the working directory, so set it first;
  • Prepare the target scene before importing (the red line at the top of the MA+JSON tab says: ">> [Important] make sure the current scene already contains the models to be assigned!").

A complete export → import flow

  1. Quick tools → Material import/export tool;
  2. Choose the Full-spectrum tab (or MA+JSON, depending on whether the other side has the plug-in);
  3. Choose an empty directory as the Working directory;
  4. Back in Maya select the models to export (or the materials, and tick The selection is materials under Export - options);
  5. Decide the export mode (default Export selection), keep Export object mapping and Export metadata ticked, and tick Pack textures when changing machines;
  6. Click Run export and wait for the notice;
  7. In the working directory confirm the output: .zmetal (plus .ameta / .mcm / textures/), or .ma plus .json;
  8. Switch to the target scene and prepare the models to receive materials first;
  9. Expand Import - basic settings ► and fill namespace / prefix / suffix if needed; keep Auto-assign objects ticked under Import - options;
  10. Click Run import (or Import from folder... for batches) and confirm the materials appear in the scene assigned to the models.

Where the output lands

  • Export: files are written into the working directory, named from the File name input or a default timestamp;
  • Import: material nodes appear in the current Maya scene's material editor and are assigned to the matching models when Auto-assign objects is ticked;
  • With Pack textures the textures sit in the material's textures/ (or are copied into the project's sourceimages/ on import).

Risks and how to undo

  • Export overwrites same-named files directly: an existing .zmetal / .ma / .json with the same name in the working directory is written over without a word. Leaving the file name empty (timestamp naming) avoids most collisions, or use a fresh working directory each time.
  • Import adds material nodes and changes assignments in the scene: save the scene first (Ctrl+S) so you can simply not save / reopen if something goes wrong.
  • Auto-assign objects on import relies on the .mcm mapping; if model names changed, tick Fuzzy matching, but fuzzy matching can match the wrong model — try one or two before a large import.
  • To undo: a bad export cannot be recovered from the overwritten working-directory files (keep export directories separate next time); a bad import is undone by not saving and reopening the scene.
