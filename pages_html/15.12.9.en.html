One-line summary: the scan window opened from Maintenance → Clean invalid assets: it lists assets missing meta.json or holding only an empty directory so you can verify, repair, clear from the list, or move them to the recycle bin.

How to open it

Top toolbar → Maintenance ▾ → Clean invalid assets. It scans the current library as soon as it opens; the cursor becomes a wait cursor while scanning.

Prerequisite: an asset library is loaded; with none loaded it asks you to open one first.

What counts as an invalid asset

StatusHow it is judgedAuto-repairable
Missing meta.json (repairable)The directory holds valid format files but lacks asset metadataYes: infer from the files and restore meta.json
Empty shell: no meta, no valid filesThe directory holds neither meta.json nor a recognizable asset fileNo: it can only be moved to the recycle bin or handled by hand

What the window contains

AreaContent
Summary line"Scanned N invalid assets (missing meta.json or empty directories only)."; with none it reads "No invalid assets found."
Hint lineExplains multi-select and what the context menu / bottom buttons do
Asset listEach row shows "name / relative path · status"
Bottom buttonsFrom the left: Rescan, Repair all, Clean all (move to recycle bin), and Close at the far right

Repair all is enabled only while the list holds repairable entries; Clean all is clickable whenever there are entries.

Context menu

ItemEffectDescription
Open asset pathOpens the directory in ExplorerCheck what is really inside
Remove from listTakes the row out of this list onlyUI only, nothing on disk; Rescan restores it
Repair: restore meta.jsonRestores metadata for the selected entriesOnly available for entries that miss meta.json and hold valid format files; empty shells are skipped with a reason

With a multi-selection the items act on all selected entries (the text states the count).

Cleaning: the only action that touches disk

  • Clicking Clean all (move to recycle bin) asks for confirmation stating the entry count;
  • After confirming, those directories move to the recycle bin, not permanent deletion;
  • The main window rescans and refreshes afterwards; to recover something, restore it from Recycle bin in the left column (8.8.3).

Risks and how to undo

OperationRiskUndo
Repairing meta.jsonMetadata is inferred from files and may not match the original intentAdjust it in the properties panel; the generated meta is saved with the asset
Clean allThe directories move to the recycle bin and disappear from the listRestore in the recycle bin (the whole asset comes back)
Remove from listOnly skipped this timeRescan restores it

Troubleshooting

SymptomCauseWhat to do
The repair button is grayThe selected entries are all empty shells with no valid format filesOpen the path to check by hand; if it really is junk, clean it
The asset still does not show after repairThe directory structure or category is not inside the libraryRun Rebuild asset index (4.1.12.2) first, then see 6.5.1
Want to recover after cleaningIt went to the recycle binLeft column Recycle bin → right-click Restore
