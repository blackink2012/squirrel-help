库体检一次给出库根、资产与分类数量、重复 UUID 和加载失败清单，是排查「资产在盘上但列表里没有」的第一步。

前置条件

  • 资产库已加载（存在活着的库管理器）。

操作步骤

  1. 打开插件窗口并确认目标库已加载。
  2. 调用命令 library_health，使用默认的 op=status。
  3. 对照下表判断问题类型。
  4. 有重复 UUID 时执行 op=fix_uuids，它会重写重复 id 并自动重扫。
  5. 有加载失败时查看每条的 reason，修正资产 meta.json 或执行 op=reload 重扫磁盘。
  6. 怀疑子库/分类配置异常时执行 op=reload_config 重读 config.json。

状态字段

字段含义
library_root当前库根目录
is_loaded库是否已加载
asset_count已索引的资产数
category_count分类数
has_duplicate_uuids是否存在重复 UUID
load_failure_count / load_failures盘上有但未扫入的资产及原因（最多列 20 条）

结果验证

  • 再次执行 op=status，has_duplicate_uuids 为 false，load_failure_count 降为 0 或明显减少。
  • 原先缺失的资产重新出现在网格与搜索结果中。

提示

  • 单项检查失败会以 *_error 字段单独返回，不会让整条体检失败。
  • 加载失败时脚本编辑器还会打印「⚠ 加载失败 N 个资产」，可与体检结果对照。
  • 工具栏的刷新按钮等价于重扫磁盘（op=reload），并会检查残留临时目录。
  • fix_uuids 会改写资产 id，收藏夹等引用旧 id 的位置可能需要人工核对。
